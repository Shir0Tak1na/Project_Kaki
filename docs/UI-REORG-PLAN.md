## 1. 判据（"该长什么样"用这十条判，不凭感觉）

1. **一个控件只有一个家**：同一件事在两处出现就是缺陷（已有 §5.9 / §5.60 两次教训：侧栏与设置页各长一份控件）。
2. **四个表面各司其职**（功能往这四个里放；放不下就是功能本身没想清）：
   - **画布**：正在动手的事（工具、笔刷、选择、拖动、图例、信息卡）；
   - **侧栏面板**：**当前上下文** —— 我正用什么工具、选中了什么、一眼能读的状态；
   - **设置页**：**出厂值 / 定义目录 / 不常动**（新对象默认值、地形与群系与路径类型目录、导出、开发者选项）；
   - **命令面板**：可绑快捷键的**动作**，与界面按钮调**同一个方法**；
3. **控件旁说明 ≤ 20 字**，超了拆成「短标题 + 可展开」；技术细节（字段名 / ID 正则 / 文件格式）不进界面。
4. **术语统一且人话**（对照表见 `UI-COPY-REVIEW.md` §3）。
5. **一个设置只有一个来源**（设计草案 §5.12）：显示偏好**不许写进地图文件**（理由见 `src/ui/settingsModel.ts:106-120`）。
6. **窄栏可用**：侧栏约 300px、设置页拖窄，**不出现横向滚动条**。
7. **一次操作 = 一条历史**；派生数据不入 `.map.md`；覆盖层永久 `pointer-events: none`（`PLAN.md` §4）。
8. **新功能先定家再写**（用户 m01803 第 5 条的归因：ISSUE-002/004 这类问题"是每次加新功能的时候不注意 UI 怎么放导致的"）——以后每加一个功能，先在本文件 §4 落位表里写明它属于哪个表面、归哪一组，再写代码；增删 UI 段落时同步更新落位表。
9. **分享不覆盖**（用户 m01833）：进地图文件的东西必须"分享出去也不会改动对方的使用设置"——地图信息 / 定义信息 / 默认值信息进文件名；UI 与渲染层设置一律留插件设置（含色带、限度、不透明度、显示方式、等值线间距、写数值）。
10. **批量编辑的字段必须是所有选中项共有的**（用户 m01902 授权"同类多对象选择"之后的边界）：同类对象可批量；**异类对象混选不做**；**对象 + 格 混合永不允许**（字段体系不同源 —— 格是数据层"值"，对象是外观；见 §2.6）。

| **接线面**（改动清单） | `settingsModel.ts`（形状 + 归一化）· `main.ts`（`overlaysFor` / `layersFor` + 5 个写入口改到"当前地图 + 镜像"）· `MapLayerManagerDeps` 的 `getLayers` / `getOverlayStyles` / `getShowLegend` 加 **canvasPath 参数**（与 W4-1b 加的 `document` 同一条路：调用点就在作用域里，每处只多传一个）· `MapBasesView` 的同名三个访问器改成带**地图路径**（它没有 canvas）· 导出按被导出的那份地图取 · 侧栏 / 设置页 / 面板的宿主接口不动（它们只调注入的 getter/setter） |
| **风险点** | ① `getOverlayStyles` 是**每帧现读**的 ⇒ 解析要走一条便宜的路（按 `mapPath` 查表，不做规范化），否则每帧白烧 CPU；② 冒烟里大量断言直接读 `plugin.getSettings().overlays` / `.layers` —— 有活动地图的场景要改成读"当前地图那一份"，无地图的场景读到的仍是模板（**与 W4-1b 那次改写同一套路**） |

**为什么不做"写进地图文件"**：见 §5.1 的三条判据 —— 它是"怎么画"，不是"这个世界的事实"；
写进去会让"分享一张图"变成"连对方的看法一起改掉"。
