## ISSUE-001 · 等值线数字：黑色 / 很大 / 不随线旋转

- **状态**：🟠 诊断中（2026-09-28 用户实测；已排除一个方向，见 §2）
- **报告时基线**：构建 79 模块 / 1214.6 KiB · `tsc` 0 · 单测 589 · 冒烟 1300 断言（场景到 46）

### 1. 现象与期望

**现象（用户原话）**：「等高线数字没弄好，还是黑色的，很大不跟着线走。」
**用户已答**：把设置里「在每个格上写出数值」**关掉**之后，数字**还在**。

**期望（设计依据 `DATA-LAYER-PLAN-v5.md` §A）**：数字用**对比色**且带描边（压在彩色场上也要看得见）；
**沿等值线**按局部切线角旋转（收进 ±90°，不许倒着看）；字号与其它标注同一条式子、不能单独放大；
数字处的等值线**真的断开**。

### 2. 我先做的代码核查（结论：**三段链路都已实现**）

| 环节 | 代码事实 |
|---|---|
| 颜色 | 等值线线色 = **该层级的色带颜色**（`fieldPlan.ts:747,763`）；标签色 = `textColorOf(线色)`（`:780`）；`halo: true` |
| 描边 | 画布 `rgba(255,255,255,0.9)`（`overlayDraw.ts:200-203`）；SVG `stroke="#ffffff" stroke-opacity=...`（`src/base/mapPreview.ts:426`） |
| 旋转 | 切线角在 `cutPolyline` 里按"中点所在那一段的方向"算（`fieldPlan.ts:696`），经 `keepUpright` 收进 ±90°（`:614-618`）；画布 `translate → rotate → (halo) → fillText → restore`（`overlayDraw.ts:188-208`）；SVG `transform="rotate(deg x y)"`（`mapPreview.ts:422`） |
| 字号 | `labelSize = max(8, grid.size × layer.deviceScale × OVERLAY_LABEL_SCALE)`（`overlayDraw.ts:171-172`，`OVERLAY_LABEL_SCALE = 0.5`）；同一式子作为"挖缝宽度"进几何（`overlayPlan.ts` 传 `grid.size × OVERLAY_LABEL_SCALE`） |

**所以要解释"黑色 / 很大 / 不随线走"，只有两个可能对象** —— 而它们**都不是"等值线标签写错了"**：

#### 对象 A：越界格标签（**会绕过你刚关掉的开关**）

`fieldPlan.ts:804` 的判定是
`showValues === true || (labelOutOfRange === true && style.outOfRange !== null)`
—— 「越界格**总是**写数值」是**故意**的（设置页文案也这么写：颜色表达不了"高多少"，越界恰恰最需要读数）。

这类标签的特征**三条全中**：

| 症状 | 越界格标签 | 等值线标签 |
|---|---|---|
| 黑色 | ✅ `color: style.textColor`（浅色锚点 → 黑），**且没有 halo** | ❌ `textColorOf(线色)` + 白描边 |
| 很大 | ✅ 同一个 `0.5 × 格半径` | 同一条式子 |
| 不随线走 | ✅ **设计如此**（格心读数必须水平） | ❌ 按切线旋转 |

#### 对象 B：真的是等值线标签 → 那问题是**设计口径**，不是实现漏做

1. **黑色**：线色来自**色带在该层级的颜色**，浅色段（温度高处/深度浅处）⇒ `textColorOf` 判成**黑**；
   而 halo 是**白色** ⇒「黑字 + 白边」压在浅色场上**等于看不见**，观感就是"一坨黑字"。
   **要改的是 §A.4 的口径**：对比色应当与**字底下的场**对比，且 **halo 必须与字色相反**（白字配深边 / 黑字配浅边）；
   或者干脆学工程图：数字用线色加深 + 断开处留白底。
2. **很大**：字号是"**半个格半径（世界单位）**"，缩放时会跟着放大 ⇒ 等值线标签应有**自己的比例**（更小），
   或改成**屏幕固定字号**（缩放时大小不变）。
3. **不随线走**：两端都实现了旋转 ⇒ 若真不转，先打印图元里的 `rotation`：
   水平段算出 0 是正常；若**所有**标签都是 0，才回来查 `cutPolyline` 与消费端。

### 3. 请用户再答一句（任一条即可定对象）

1. 那些数字是**零星几个**（只在最热/最冷的格），还是**沿着等值线成串**出现？
2. 数字**旁边有断开的线**吗？（等值线标签会把线挖断；格心读数附近没有线）
3. **把整个「温度」图层关掉**，数字还在吗？（还在 ⇒ 是另一个数据层，例如深度的越界格标签）

### 4. 修法（按对象二选一）

**若为对象 A（越界格标签）** —— 它不是缺陷，是**没讲清的分工**：

1. 设置页那一项的描述改成「在所有**格心**写出数值（等值线上的数字是另一回事；越界格始终写）」——零风险，先做；
2. 给越界格标签一个**单独的、更小的比例**（例如 0.4），与等值线标签分开；
3. 允许用户**关掉**越界格标签（现在无开关）。

**若为对象 B（等值线标签）**：

1. **对比色口径改掉**（同时改 `DATA-LAYER-PLAN-v5.md` §A.4）：
   用**字底下的场色**判黑白，并让 **halo 与字色相反**；浅色段不再出现"黑字白边"；
2. **字号独立**：新增 `CONTOUR_LABEL_SCALE`（建议 0.35）或改为屏幕固定字号；
3. 若 `rotation` 恒为 0：查 `cutPolyline` 的取段（`.filter(length >= gap×4)` 后按长度排序）
   与 `keepUpright`，并补 §5 的断言。

### 5. 修完必须补的断言（要能变红）

1. **对比色**：文字图元的 `color` 必须与 halo **相反**（黑字 → 非白边；白字 → 深边），
   且对**浅色线色**不得生成"黑字 + 白边"的组合；
2. **旋转**：给定一条已知斜率的等值线，图元 `rotation` 必须等于该处切线角（±90° 内）；
3. **画布**：绘制文字期间 `ctx` 的变换**包含旋转**，`fillStyle === primitive.color`，halo 时**先 `strokeText` 后 `fillText`**；
4. **字号**：等值线标签的字号**不随缩放无限放大**（若采用屏幕固定字号，直接断言"缩放 2× 后字号不变"）；
5. **导出一致**：SVG 里同一文字的 `fill` / `transform` / 描边与画布同源（几何只有一份）。

### 6. 验收（可判伪，真实库）

1. 只开等值线（关掉逐格数值）→ 数字压在**深色场**上看得清，压在**浅色场**上同样看得清（不再"一坨黑"）；
2. 斜的等值线上数字**跟着斜**，水平线上水平，**没有数字倒着**；
3. 字号**明显小于格宽**，缩放到 200% 时不变成巨字；
4. 数字处等值线**真的断开**（放大看没有线穿过数字）；
5. 导出 SVG/PNG 与画布**一致**（颜色、倾斜、断线、字号）。
