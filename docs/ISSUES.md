## ISSUE-001 · 等值线数字：黑色 / 太大 / 不随线旋转

- **状态**：🔴 待修（2026-09-28 用户实测报出；用户原话：「验证通过，但是等高线数字没弄好还是黑色的，
  很大不跟着线走」）
- **报告时的基线**：构建 79 模块 / 1214.6 KiB · `tsc` 0 · 单测 589 · 冒烟 1300 断言（场景到 46）

### 1. 期望行为（设计依据：`DATA-LAYER-PLAN-v5.md` §A）

| 项 | 要求 |
|---|---|
| 颜色 | 用 `textColorOf(线色)` 的**对比色**（按亮度自动选黑/白），并带**白色描边（halo）**，压在彩色场上也要看得见 |
| 方向 | **沿等值线走**：按落点处的**局部切线角**旋转；限制在 ±90° 内镜像一次（数字不许倒着看） |
| 大小 | 与其它数值标注**同一条式子**（`OVERLAY_LABEL_SCALE × 半径`），不能单独放大 |
| 断线 | 数字处的线要**真的断开**（挖掉文字宽度那一段），不是拿背景色盖住 |

### 2. 我先做的代码核查（**结论：这两条链路本身都实现了**）

| 位置 | 事实 |

| `src/render/overlayDraw.ts:184-210` | 画布端：`translate(落点) → rotate(rotation) →（halo 时白描边 0.9）→ fillStyle = primitive.color → fillText`，用完 `restore()` |

| `src/base/mapPreview.ts`（导出侧） | 文字图元用 `transform="rotate(deg x y)"`（度数换算在那边） |
| `src/render/fieldPlan.ts:808-818` | **另一类**文字：逐格数值（`kind:'text'`，`color: style.textColor`，**没有 rotation**）——它本来就该是**水平**的，字号同样走 `labelSize` |

### 3. 最可能的解释（**先回答下面三个问题再动手**，否则会修错对象）

三个症状**同时**符合"逐格数值标签"的特征，而**不符合**等值线标签的特征：

| 症状 | 逐格数值标签（`showValues` 打开时） | 等值线标签 |
|---|---|---|
| 黑色 | ✅ 用 `style.textColor`（浅色锚点 → 黑） | ❌ 用 `textColorOf(线色)`，且带白描边 |
| 很大 | ✅ `0.5 × 格半径`（缩放大时更明显） | 同一条式子，但等值线标签通常更稀疏、更显眼 |
| 不随线走 | ✅ **设计如此**（格心读数必须水平） | ❌ 应按切线旋转 |

**待判问题（请用户 30 秒回答，任一条就能定位）**：

1. **把设置里「在每个格上写出数值」关掉**，只留等值线 → 数字还在吗？
   - 不在了 ⇒ 你看到的就是**逐格数值**（ISSUE-001-A，见 §4A）；
   - 还在、且仍黑且水平 ⇒ 是**等值线标签**的问题（ISSUE-001-B，见 §4B）。
2. 当时**画布缩放**是多少？（等值线/数值字号是"位图像素"，缩放会跟着变大）
3. 你是**在画布上**看的，还是在**导出的 SVG/PNG**里看的？（两条链路各自可能有一处没接上）

### 4A. 若确认是"逐格数值"（最可能）

这**不是缺陷**，而是**没被讲清的分工**。可选的改法（按代价排序）：

1. **界面写明**：设置里那一项的描述改成「在所有格心写出数值（与等值线上的数字是两回事）」——
   零风险，先做；
2. **默认更小**：把逐格数值单独给一个比例（例如 `0.4`），与等值线标签分开（现在是共用 `OVERLAY_LABEL_SCALE`）；
3. **自动抑制**：打开连续场时，默认**不给兜底格**写数值（现在是 `showValues` 全开就全写）。

### 4B. 若确认是"等值线标签"

按现象逐条查（每条都能一眼判定）：

| 现象 | 先查 | 可能的根因 |
|---|---|---|
| 黑色 | 打印 `textColorOf(线色)` 的实际返回值；看**导出 SVG** 里的 `fill` 与描边 | ① 等值线本身颜色很浅 ⇒ 对比色就是黑（这是**按设计**，但压在深色场上不可读，需要改规则：**以"场/背景"的亮度为准**，而不是以线色为准）；② 导出侧没实现 halo（只画 `fill`）⇒ 黑字无白边；③ 文字图元被别的分支覆盖了颜色 |
| 很大 | 在**100% 缩放**下看是否仍大；核对 `rasterRadius` 是否被乘了两次 `deviceScale` | 与格半径绑定不合适（等值线数字应该比格心读数**再小一档**，或改为"屏幕固定字号"） |
| 不随线走 | 在 `overlayDraw.ts:188` 打一行日志看 `primitive.rotation` 是否为 0 | ① 切线角算出来就是 0（水平段，属正常）；② `cut.angle` 没被写进图元；③ 画布走了 `rotation === 0` 的分支；④ 导出侧 rotate 的**圆心**写错（`rotate(deg x y)` 的 (x,y) 必须是落点） |

### 5. 建议补的自动化断言（修完必须有，且要能变红）

1. `fieldPlan`：给定一条已知斜率的等值线，**文字图元的 `rotation` 必须等于该处切线角**（±90° 内）；
2. `fieldPlan`：文字图元的 `color` **必须等于 `textColorOf(该条线色)`**，且 `halo === true`；
3. `overlayDraw`：绘制文字期间 `ctx` 的变换**包含旋转**（桩里快照 `ctx.rotation` 或记录 `rotate()` 调用），
   且 `fillStyle === primitive.color`、halo 时**先 `strokeText` 后 `fillText`**；
4. 字号：`labelSize` **不随** `grid.size` 之外的第二个缩放因子变化（防"乘两次 deviceScale"）；
5. 导出：SVG 里对应文字的 `fill` 与 `transform` 与画布同源（几何只有一份）。

### 6. 验收（可判伪，先在真实库做）

1. 打开温度图层 + 连续场 + 「在每个格上写出数值」**关** → 等值线上出现数字；
2. 数字颜色：压在深色场上的数字**看得清**（有白边或本身是浅色），不再是"黑压深蓝"；
3. 数字方向：斜的等值线上数字**跟着斜**，水平的线上数字水平；**没有数字是倒着的**；
4. 大小：与格心读数比**不更大**；缩放到 100% 时明显小于格宽；
5. 断线：数字位置的等值线**真的断开**（放大看没有"线穿过数字"）；
6. 导出 SVG/PNG 与画布**一致**（同样颜色、同样倾斜、同样断线）。
