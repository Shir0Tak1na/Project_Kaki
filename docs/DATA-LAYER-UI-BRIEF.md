## 2. 已经落地的第一块（W1，2026-09-29 —— **不要重做**）

**模型文件**：src/render/colorRamp.ts

- RangeStyle（:40）新增**必填** farColor / farTextColor：分别是"远远低于 / 远远高于"时渐变到的**极色**与**它上面的字色**。
  **farColor === color 表示这一侧不渐变**（老设置里没有这两个键 ⇒ normalizeRangeStyle() 回退成"不渐变"，行为与升级前一致）。
- **位置与值的换算**（轴与图例共用同一套，别另写一份）：RampBounds（:132）、rampBounds(stops)（:139）、
  positionForValue(value, bounds)（:153，**不夹取**，越界值会算出 <0 / >1 的位置）、valueForPosition()（:158，逆运算）。
- **越界取色**：colorForValue()（:381）越界时走内部 outOfRangeValue(ramp, side, distance)：
  t = clamp(distance / span, 0, 1)（span = 最高锚点值 − 最低锚点值），t <= 0 逐字返回端色、t >= 1 逐字返回**极色**，
  中间走 Oklab 插值，字色在两端的候选里按对比度挑（pickReadableTextColor()）。
- **温度出厂色**（defaultTemperatureRamp() :90）：低温 { color:#0000ff, textColor:#ffffff, farColor:#ffffff, farTextColor:深字 }、
  高温 { color:#ff0000, textColor:#ffffff, farColor:#000000, farTextColor:#ffffff } ⇒ 越冷越白、越热越黑。
- **深度出厂色**（defaultDepthRamp() :116）：stops = -4000 #000000 / 0 #808080 / 4000 #ffffff，
  两端本身就是极色 ⇒ **两端不另做渐变**（farColor === color），over.textColor 用深字。**这改掉了原来那条蓝色深度色带。**
- 为什么 farColor === color 要短路：Oklab 往返会把 #0000ff 变成 #0001ff，逐字断言（以及用户明确要的"蓝底白字"）会漂。

**测试 / 冒烟**：tests/colorRamp.test.ts（新增"越界色按距离渐变成极色、一个跨度后饱和、过渡段换字色"）、

## 3. W2 · 侧栏的「轴」（要做的）

**现在的样子**：锚点是**逐行控件**，不是一条轴 —— src/ui/settingsSections.ts 的
renderOverlayFieldSection()（:95，整段约 92–285 行）给每个锚点画一行"值 + 颜色"输入，另给"低于下限 / 高于上限"各一个颜色选择器。
设置页与侧栏面板**共用这一份渲染**（这是既有纪律，见 §6）。

**要变成**：一条**轴**（横条），轴上是按**值**的比例摆的颜色锚点（用 positionForValue()），
两端是"低于最低限度 / 高于最高限度"的端帽（各自带颜色 **+ 渐变到的极色**）。

用户 m01702 对这条轴的三条口径（**照做，别再问一遍**）：

- **方向**：常规数轴方向（低端在左、高端在右）。
- **不画刻度**：用户原话"没有刻度。只给程序计算渐变率预留刻度" ⇒ 轴上**不显示刻度数字**；
  刻度 / 间距只是程序算**渐变率**用的内部量（相邻锚点的值之差决定那一段的渐变率）。
- **两端的锚点可以拖动**，拖动**只改数值、不改端点颜色**（端色是用户挑的颜色，拖值不动它）。

**能直接复用的**：

| 东西 | 在哪 | 说明 |
|---|---|---|
| 位置 / 值换算 | src/render/colorRamp.ts:132-169 | rampBounds / positionForValue / valueForPosition，**轴与图例必须共用** |
| 渐变 CSS | src/render/legend.ts:338 rampGradientCss(info) | 现在只吃 LegendRampInfo（:32）的 stops + underColor / overColor **两个纯色** |
| 图例条 DOM | src/ui/MapLegend.ts:118-126 | bar.style.backgroundImage = rampGradientCss(ramp) —— 轴可以照它做 |
| 校验文案 | src/render/colorRamp.ts:464 describeRampProblem() | 锚点太少 / 值重复等，直接用它的中文 |
| 锚点数量上下限 | RAMP_MIN_STOPS = 2（:61）/ RAMP_MAX_STOPS = 32（:63） | 删到 2 个就不能再删 |

> **接口缺口（值得先想清楚）**：LegendRampInfo 现在只表达"越界两端各一个纯色"，
> 而 W1 的模型是"端色 + 极色 + 渐变"。做轴（和让图例也显示渐变端帽）时**要扩这个接口**，
> 别在 MapLegend.ts 里再复制一套插值。

**W2 的可判伪验收清单**：① 新建锚点 → 它落在轴上与它的值成比例的位置；
② 改一个中间锚点的值 → 相邻两段的"渐变率"随之变化，且**别的锚点不动**；
③ 锚点删到剩 2 个时删除入口不可用（不是静默无效）；
④ 越出下限 / 上限的格色 = 轴上左右端帽的渐变结果（在一样的值上重算一次，色值一致）；
⑤ 关掉面板再打开 / 重载插件 → 锚点与颜色原样（值都**存着**、不是画出来的；按 §5-1 每张地图各存一份）；
⑥ 设置页与侧栏改的是**同一份**（一边改完，另一边重绘后必须一致）。

## 5. 已确认的口径（用户 m01702 答复 · 逐字）

> 1.在对应的地图独立编辑。2.端的锚点可以拖动修改值，只不过不会影响端点的颜色。3.按照常规的数轴的方向，
> 没有刻度。只给程序计算渐变率预留刻度。

1. **最低 / 最高限度这两个数值：在对应的地图上独立编辑** —— 不在插件设置页统一编辑，也**不是全局一套**，
   而是**哪张地图上改、就只影响哪张地图**（结合 m01598：出厂值仍然承担"新地图的默认值"的角色）。
   ⚠️ **这条要动存储，动手前请用户对一次**：现在色带是**按字段全局一份** ——
   `OverlayStyles = Record<FieldId, OverlayStyle>`（src/render/overlayFields.ts:389）存在
   `pluginSettings.overlays`（src/ui/settingsModel.ts:120，写入口在 src/main.ts:2358；
   `pluginSettings.layers` 同理，src/main.ts:333 / :1052），改一次温度色带**所有地图一起变**。
   要做到"按地图独立"，色带（含两个限度值）就得按 **地图 + 字段**分键存储，
   并且**老配置要迁移**（老的那一份当作每张地图的初始值）。
   ⚠️ **还有一条现成的纪律别踩**：显示偏好**不许写进地图文件** —— src/ui/settingsModel.ts:106-120 写明
   "把显示偏好写进数据 = 换个看法就改了用户的地图 + 污染 Git diff"，且每个设置只有一个来源（设计草案 §5.12）。
   所以"按地图"的色带只能存进 **插件设置里、按地图标识分键**；而 `CartographerSettings`（settingsModel.ts:34-140）
   现在**没有任何"按地图分键"的先例**（全是全局一份），地图标识用什么（文件路径？）要在这个任务里定下来。
2. **两端的锚点可以拖动修改值**，但**拖动不影响端点的颜色**（端色只由用户挑的颜色决定）。
   ⇒ 在轴上拖端点 = 改这张地图的两个限度值；这与第 1 条不冲突。
3. **轴按常规数轴方向**（低端在左、高端在右），**界面上不显示刻度**；刻度只是**程序算渐变率**的内部量。
   ⇒ 不要在轴下方做"刻度读数"（原先 W2 的设想里有读数一项，按这条**去掉**）。
