## 0. 决策记录（与原稿的差异，**先读这一节**）

### D1 · 连续场"颜色面"在导出里怎么表达 → **定稿：(a) 内联栅格 + 三条硬约束**

审查当时我倾向 (b)（导出时颜色面退回逐格多边形，纯矢量），理由是守住仓库既有的
「`mapPreview` 的 SVG 从不内联图片」。**但出现新证据后改判为 (a)**，理由三条：

1. 实现里已经出现 `src/render/pngEncode.ts`（纯模块里的 PNG 编码器），走的就是内联栅格；
2. **那条旧口径针对的是"用户库内的图片"**（无上限、外部依赖、可能是几十 MB 的照片）；
   而连续场的栅格是**派生的**、且被 `MAX_FIELD_DIMENSION = 256` 限死 ⇒ 256×256 的 PNG
   在几十 KB 量级，内联进 SVG 完全可接受，**且仍然自包含**（data URL 不依赖库内文件）；
3. (b) 会让"几何只有一份"这句承诺对**颜色面**失效（画布一份栅格、导出一份多边形），
   而两份几何一旦分叉，长期一定漂移 —— 这正是本仓库反复吃过的亏。

**所以定稿 (a)，但必须带三条硬约束**（缺一不可）：

| # | 约束 | 为什么 |
|---|---|---|
| a1 | 栅格必须由**同一份 `FieldPlan`** 生成，不许在导出侧另写采样/插值 | 保住"几何只有一份" |
| a2 | 分辨率上限 = `MAX_FIELD_DIMENSION`（256），编码为 PNG（复用 `pngEncode.ts`） | 体积可预测 |
| a3 | **体积上限**：内联 data URL 超过 **128 KiB** 时**退回逐格多边形**（纯矢量兜底），并在导出报告里写明用了哪条路 | 防止"地图一大、导出的 SVG 就变成十几 MB" |

**连带要改的文档口径**（必须改，否则下一个人会以为 (a) 违规）：
`README` / `EXTENSION-POINTS` 里「SVG 导出不内联图片」要改写成
**"不内联用户库内的图片；派生的、有上限的栅格可以内联（上限 128 KiB，超限退回矢量）"**。

### D2 · 连续场的采样范围与缓存 → **定稿：按"有值格的包围盒"整图采样一次，缓存键不含视口**

原稿没写。定稿与理由：

- **采样范围** = 「有值格（真值 **或** 被 §B 默认值兜底的格）的包围盒」，
  **不是**整幅世界矩形、也不是视口 —— 这样 256 个采样点全部用在有数据的区域上（精度最高）；
- **缓存键** = `字段 + 数据版本（相关格的哈希）+ 显示参数（色带/层级数/不透明度/单位）`，**不含视口**；
  ⇒ 平移不重算（流畅），但**地图越大精度越低**（256 上限）；
- 这是**有意的取舍**，要求：① 在手册里写明"大地图上连续场精度有限"；
  ② 断言"平移一帧后没有重新采样"（用计数或缓存命中标志证明）；
  ③ 采样上限做成可调设置**留到以后**，本轮不做。

（**不是**打开覆盖层的 pointer-events —— 见 §2 硬约束 1）：

| 输入 | 未激活工具 | 「选择」工具 | 「笔刷」工具 |
|---|---|---|---|
| 左键拖动 | 原生 | **框选 / 笔迹选择** | **刷** |
| `Shift` + 左键 | 原生 | **加选** | 不启用（保持简单） |
| `Alt` + 左键 | 原生 | **单独取消这一格 / 这一片**（不是集合取补） | — |
| 右键 / 中键 / 滚轮 / 空格拖动 | 原生 | **仍然原生** | **仍然原生** |
| `Esc` | 原生 | **先清空选择；选择已空时再退出工具** | 退出工具 |

**硬纪律**：插件永不接管右键、中键、滚轮与空格拖动（那是 Canvas 的平移与菜单手势）。

### C.2 筛选器 = 可扩展的**规则 IR**（照 Minecraft 目标选择器的形状）

```
规则 := { 连接: 'and' | 'or', 取反: boolean, 子句: 子句[] }
子句 := { 键: 规则键, 运算: 运算符, 值: 值 }
```

**规则登记表**（新建 `src/render/selectionRules.ts`），一行一条规则：

| 字段 | 作用 |
|---|---|
| `key` | 键名（`terrain` / `temp` / `depth` / `biome` / `has` …） |
| `label` | 下拉里显示的名字 |
| `ops` | 这条规则允许的运算符（`=` `≠` `>` `≥` `<` `≤` `in` `between` `exists`） |
| `valueKind` | 值的形状（枚举 / 数值 / 范围 / 布尔）→ 决定 UI 渲染成下拉、数字框还是两个数字框 |
| `match(cell, value)` | 纯函数：这一格满不满足 |
| `describe(value)` | 纯函数：这条子句怎么念（"温度 ≥ 20 ℃"） |

→ **加一条筛选规则 = 加一行**（与"加一个数据层字段 = 加两行"同一条纪律）。

**上手难度：做成 UI 子句构建器，不做文本语法**：

```
筛选器
  [ 地形   ▾ ] [ =       ▾ ] [ 森林 ▾ ]        [×]
  [ 温度   ▾ ] [ between ▾ ] [ 10 ] [ 30 ]     [×]
  [ 生物群系 ▾ ] [ in    ▾ ] [ 森林 ][ 苔原 ]  [×]
  连接：( ● AND   ○ OR )      取反：[ ]
  [ + 添加子句 ]   应用到选择 →（ 替换 / 并入 / 移出 ）
  说明：温度 ≥ 10 且 ≤ 30、且 地形 = 森林          ← 人话回显（`describe`）
```

四条"易上手"措施：① 运算符下拉只列该规则允许的（来自 `ops`）；
② 输入控件形状由 `valueKind` 决定；③ **人话回显**放在子句列表下方；④ **即时校验**：
非法值（`min > max`、空值）在那一行标红并说明，且**不把这个子句算进选择**。

**留的窗口**：文本语法 + 补全本轮不做；IR 是共享的，将来只是"同一份 IR 的另一个输入方式"。

**出厂规则**：地形类型 · 温度范围 · 深度范围 · 生物群系类型 · 有/无该字段（`exists`）·
**当前选择内**（见下）。

> **生物群系给筛选器加了第二条规则**（见 `docs/BIOMES.md` §3）：除精确匹配 `biome`（枚举多选）之外，
> 还有按**标签**匹配的 `biomeTag`（`in [forest, polar, arid, artificial, ...]`）。
> 这样 34 个群系不是逐个勾，而是按"层位 / 气候 / 植被 / 特殊"四类标签一次命中一组，
> 并允许**一对多**（「所有森林类」= `biomeTag in [forest]`）。这条设计参照 Minecraft：
> 它在 1.19 正是**删掉了群系的 `category` 字段、把归类整体移到群系标签**，
> 因为一个群系常同时属于多个组 —— 单一枚举字段迟早会逼出任意选择。

**与集合运算的分工**（写清，避免混成一锅）：
- **规则**只做"逐格谓词"（这一格满不满足）；
- **动作**负责集合运算：替换选择 / 并入选择 / 移出选择；
- **连通扩展**（按同地形连通）也做成**动作**，不是规则（它要邻域遍历）。
- ⚠️ **「当前选择内」不是逐格谓词**（依赖当前选择 = 上下文相关），按上面的分工它**不能当规则**：
  做成**动作**（"在当前选择内再筛" = 用新规则 intersect 现选择），
  或把选择作为**纯入参**传给 `match`。二选一，别写成"规则"。

### C.4 选择信息卡（**右上角，取代侧栏的详情显示**）

- 位置：**原右上角工具浮窗处**（`.fc-toolbar` 现在 `top: 8px; right: 76px` → 浮窗搬去左上角，卡片占此处）；

| 情形 | 显示 |
|---|---|
| 空闲 / 编辑中 | 状态条：`编辑：地形笔刷 · 森林` / `空闲` |
| **单选** | 坐标 `(q,r)`、地形、温度、深度、生物群系（没有的字段写"未填"，**不猜 0**） |
| **多选** | 总格数 · 坐标范围（q/r 最小–最大）· 包含的地形种类 · **温度的众数** · **深度的平均数** · **生物群系类型清单（各有哪些，不是个数）** |

统计口径（写死）：众数 / 平均数**只统计有该字段值的格**，并标注"其中 N 格没有数据"；

（否则"颜色 = 有数据"的直觉会被打破，见 §B.3）。

### C.5 多选后的编辑

侧栏检查器变「**整批编辑**」：温度 / 深度 / 生物群系 + 「清除该值」，**一次提交 = 一条历史**。
跨越"有值 / 无值"混合时输入框留空并提示"这批里有 N 格没有数据"，**不猜共同值**。

> **状态：已完成（2026-09-29，§E 轮；与 §D 同轮收尾）** —— **当时的**基线同 §D（85 模块 / 1401.0 KiB ·

> 逐条回执：三条硬口径**全部落地并各有断言**（① 数值框初始为空 → 冒烟"切到温度层后数值框是空的"；
> ② 空着 / 未确认不生效且状态条说原因 → `brushReadiness()` 返回 `{ok:false, reason}`，
> 状态条显示 `编辑：数据层笔刷 · 请先填一个数值`；③ 换层 / 换算法**保留数字但打回未确认**）。
> 逐格算法（`applyBrushOp`）与 §E 那张表**逐行对应**：`＋/－` 从每格默认值起算并固化、`× / ÷` 跳过无值格、
> `÷ 0` 在整笔上拦下（不逐格产生 `Infinity`）；一笔 = 一条历史（复用 `brushPath.ts` 的采样口径）。
> 分类字段只有「设为 ID」—— 切到生物群系时算法组与数值框**整组隐藏**（摆着点不动只会让人以为坏了）。
> ⚠️ 与原稿的一处不同：原稿的"换模式"指的就是换算法按钮，本轮把"换层"也并进同一条打回规则
> （换层是更容易出事故的那一种：温度层上还留着给深度填的 +200）。

| 模式 | 语义 | 无值的格 |
|---|---|---|
| ＋ / − | `prev ± n` | 从**默认值**起算（没默认值就从 0）—— **会把默认值固化进该格**，UI 要说明 |
| × / ÷ | `prev × k` / `prev ÷ k` | **跳过**；`k = 0` **拒绝并说明** |

**"值由你确认"的三条硬口径**：
1. **不给默认值**：数值框初始为空，**不预填** `+2` 这类出厂值；
2. **空着不能刷**：值为空 / 非法时笔刷**不生效**，状态条写明原因（"请先填一个数值"）；
3. **不静默沿用**：换层或换模式后**不自动带**上一层的数值 —— 实现上**保留数字但标记为"未确认"**
   （灰掉/待回车），既满足这条又不用用户重打；回车 = 确认。

**最简做法**：不新增笔刷参数，半径与骨架复用地形笔刷；一笔 = 一条历史
（复用 `src/render/brushPath.ts` 的采样口径；**注意**：原稿说的 `cellFieldOpsFromPrevious`
**在仓库里不存在**，别去找它）。
