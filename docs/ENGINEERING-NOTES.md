---

Project Kaki（译名 Project 垣）是一个 Obsidian 六边形客制化地图创作插件：
在 Canvas 中绘制自定义六边形地形图、河流、领域范围与地标，并通过 Base 导航地图与笔记。

插件 ID 为 `project-kaki`（`scripts/deploy.mjs` 会自动把旧 ID `fictional-cartographer` 目录下的
设置迁移过来并删掉旧目录）。地图文档类型 `fictional-cartographer-map`、Base 视图 ID `fictional-map`
与面板视图 ID `fictional-cartographer-panel` **保持原样**：它们是写在用户文件与工作区布局里的持久化标识，
改了会让已有地图、已保存的 Base 与侧栏布局失效（理由见 §5.8）。

## 2. 快速上手（本环境下的正确命令）


（`check` = 构建 → 测试 → 冒烟 → 部署）。**但在本沙箱里 `npm run <script>` 可能报 `spawn EPERM`**，
直接跑 `node ...` 最稳。

### 版本管理（GitHub：`Shir0Tak1na/Project_Kaki`，Apache-2.0）

远端仓库已接好（`origin`，分支 `main`）。提交前请按顺序跑完 **构建 → 类型检查 → 单测 → 冒烟**，

两条注意事项：

  所以 clone 之后要装进 `.obsidian/plugins/` 得先构建。想让仓库直接可用，就把 `.gitignore`
  里的 `main.js` 那行删掉并提交它。

  强推会把它删掉。本地历史是"合并远端初始提交"的结果，正常 `push` 即可。
- 本机 git 曾在 `E:\ObsidianPulgins` 上报 `dubious ownership`（目录属主是 Administrators），
  修法是把该路径加进 `safe.directory`（已加）：`git config --global --add safe.directory E:/ObsidianPulgins/fictional-cartographer`。

### ⚠️ 本沙箱环境的限制（违反会得到莫名的 `Access is denied` / `EPERM`）

| 现象 | 原因 | 做法 |
|---|---|---|
| 命令输出为空 / `Access is denied` | 把子进程输出接进管道会被拒绝 | **不要用 `\|`、`>`、`2>&1`**；想要留档就让脚本自己写文件 |
| `npm install` 报 `EPERM ... npm-cache` | npm 缓存在工作区之外 | 已在 `.npmrc` 指向工作区内的 `.npm-cache/`，不要改回去（该文件含本机绝对路径，已被 git 忽略） |
| `npm install` 报 `spawn EPERM` | 生命周期脚本要 spawn 子进程 | 一律加 `--ignore-scripts` |
| `node --test` 报 `spawn EPERM` | 测试运行器默认每个文件起子进程 | 加 `--test-isolation=none` |

### 构建方式为什么不是 esbuild

社区插件一般用 esbuild；本项目的 `scripts/build.mjs` 用 TypeScript 编译器 API 在进程内完成编译，
再把自己产出的 CommonJS 模块内联成单个 `main.js`。**产出与 esbuild 等价**（CJS、单文件、
`obsidian` 保持 external）。原因：本沙箱禁止 spawn 子进程并经命名管道通信，
原生 esbuild 与 esbuild-wasm 在 Node 下都要 spawn，因此都不可用。
没有沙箱限制的机器上仍可 `npm run build:esbuild`。

### 部署与协作流程

插件产物只有三个文件：`main.js` / `manifest.json` / `styles.css`（**不含 package.json**，
它带 `"type": "module"` 会让 Obsidian 的 CJS 加载混乱）。
`scripts/deploy.mjs` 把它们复制到 `test-vault`；真实库 `D:\TOS\万千旅路｜Thousands of Sands`
是用户的**正式库**，除非用户显式设置 `FC_VAULT`，**不要碰**。

一直以来的协作循环是：**改完就部署 → 给用户一份可判伪的验证清单 → 用户 `Ctrl+R` 重载后试用并报告
→ 复现并修**。这个循环非常有效：每一轮用户报告都找到了真 bug。请保持它。

### 架构上的两条铁律

1. **私有 API 只能出现在 `src/canvas/CanvasAdapter.ts`**。上层出现 `canvas.tZoom` 这类写法即视为缺陷。
2. **能算的都做成纯函数**（几何、布局、行模型、op 逆运算）并与 DOM/obsidian 解耦 ——
   这是本项目"能在没有 Obsidian 的情况下测"的唯一前提。`src/base/viewContract.ts` 刻意不
   import obsidian 就是这个原因（否则单测会因 `import 'obsidian'` 直接失败）。

## 4. 数据格式（可直接照抄的契约）

### 4.1 地图文档 `Maps/World.map.md`

````markdown
---
type: fictional-cartographer-map
fc-version: 1
name: "World"
canvases:
  - "Maps/World.canvas"
---

```json
{
  "version": 1,
  "grid": { "orientation": "pointy", "size": 40 },
  "terrain": { "0_0": { "t": "forest" }, "1_0": { "t": "water", "c": "#38bdf8" } },
  "markers": [{ "id": "m1", "label": "龙脊城", "p": [100, 50], "icon": "city", "link": "Locations/龙脊城.md" }],
  "paths":   [{ "id": "p1", "type": "river", "pts": [[0,0],[100,100]], "width": 8, "color": "#4a9fd8",
                "label": "北境商路", "smooth": true, "taper": true, "cap": "round", "join": "round" }],
  "regions": [{ "id": "r1", "label": "北境领", "pts": [[0,0],[100,0],[100,100]],
                "color": "#44cf6e", "opacity": 0.22,
                "type": "realm", "borderColor": "#101010", "borderWidth": 3, "borderDash": [6, 3] }]
}
```
````

- 地形键是**轴向格键** `"q_r"`；序列化时按键排序（Git diff 稳定），实测 **28 字节/格**。
- 标记/路径/区域用**世界坐标**（连续空间），不像地形那样量化到格。
- `label` 是路径/区域的名称；命名是可撤销的 op。
- `mode`（路径与区域）：`"interior"`（默认，穿过格子内部）、`"edge"`（沿六边形边）、
  或 `"edge-step"`（逐边：每次点击前进一条边）。
  **几何在提交时就已经转换好**了（`pts` 就是沿格边的顶点序列），渲染不读这个字段，
  它用于界面回显与将来的"重新吸附"。缺省即 `interior` → 旧地图完全兼容。
- **`type` 是"标识"而不是"画法"**：画法参数（颜色/线宽/虚线/端点/连接）**存在每个对象自己身上**，
  所以改设置里的类型参数**不影响已画好的对象**（§5.12 的"唯一来源"说的是"类型的默认值"，
  不是"对象的当前值"）。`paths[].type` 目前可以是内置 4 种（`river` / `road` / `trade-route` / `border`）
  或用户自定义的 `custom:xxx`；`regions[].type` 可以是内置 6 种（`realm` / `empire` / `duchy` /
  `diocese` / `wilderness` / `sea`）或 `custom:xxx` —— **两者都可以是"本机没有定义"的值，且必须能原样往返**。
- 路径新增的两个可选字段：`cap`（`butt` / `round` / `square`）与 `join`（`miter` / `round` / `bevel`）。
  **缺省 = 绘制层用 `round`**，也就是升级前硬编码的值 → 旧地图渲染结果逐像素不变。
- 区域新增的三个可选字段：`type`（见上）、`borderColor`（缺省/`null` = **跟随填充色**）、
  `borderDash`（缺省/`[]` = 实线；非空偶数数组 = 虚线，与路径虚线同一套三态语义）。
  **旧区域没有 `type`：读取时保持"没有"、写回时也不补** —— 老地图文件逐字节不变，
  图例仍按颜色反查内置类型的名字（`regionLabelForColor`）。
- 未知顶层字段**原样保留**（前向兼容）；`fc-version` 高于支持版本时**只读打开，绝不写回**。
- **"认不出的标识一律保留"是本项目的稳定承诺**（不只是一条功能说明），四条已经统一到同一口径：
  `terrain[].t`、`markers[].icon`、`paths[].type`、`regions[].type` ——
  认不出就**原样往返 + 一条「已保留」告警**，回退视觉由绘制层负责，**对象与该字段都不会被改写或丢弃**。
  只有"完全不可能当 ID"的值（非字符串 / 空串 / 含空白或控制字符 / 超长）才回退，
  而且**回退也不丢对象**。理由与三次事故见 §5.11、§5.26、§5.27。

### 4.2 笔记属性（Base 视图 ↔ 地图标记的桥）

```yaml
---
coordinates: [320, -140]   # 也接受 {x: 320, y: -140} 或 "320,-140"
map-type: city             # city/town/fortress/ruin/port/temple/mountain-peak/cave/tower，缺省 town
region: 北境王国            # 可选，用于分组
---
```

### 4.3 Base 视图

- 视图类型 id：`fictional-map`（`.base` 里写 `type: fictional-map`）
- 视图选项 key：`mapFile` / `coordProperty` / `typeProperty` / `regionProperty` / `sortBy`
- **不要用 `shouldHide`**：它在 Obsidian 1.10.2 变更过签名（已知破坏性变更）。
- 起始文件可用命令「创建地图 Base 文件（表格视图）」生成，或调 `buildStarterBaseFile()`。
- 地图文档加载成功后，表格上方会显示地图缩略图；缩略图宽度随 Base 容器变化，地图内容使用统一的 X/Y 比例并自动居中留白。
- 缩略图中的地图标记、路径、区域、文字标注和笔记坐标点都可点击，并跳转到对应的地图文档或笔记；地形格没有独立文件，因此不提供文件跳转。
- Canvas 地图工具条提供地图层停用按钮，并避开 Obsidian 原生缩放/卡片控件；设置页提供六边形网格显示开关。

### 4.4 定义文件（自定义资源的导入 / 导出，`version: 2`）

写在**库根目录**（刻意：它是插件级资源，与某张地图无关，也不必先打开 Canvas），
文件名形如 `project-kaki-definitions-<日期>-<时分>.json`；**重名绝不覆盖**，
走与 SVG/PNG/报告同一份 `uniqueExportPath`（`-2`、`-3`……）。

```json
{
  "version": 2,
  "generator": "project-kaki 1.0.0",
  "terrains":   [ /* 自定义地形 */ ],
  "markers":    [ /* 自定义标记 */ ],
  "pathTypes":  [ /* 自定义路径类型 */ ],
  "regionTypes":[ /* 自定义区域类型 */ ]
}
```

- **内置类型不进文件**（内置 4 种路径 / 6 种区域 / 9 种地形 / 9 种图标在每个库里都存在，
  导出它们在导入侧只会得到一串"已有同 ID"，既带不走东西又像导入失败）。
  代价是"内置类型的画笔参数不随文件分享"——这是取舍，不是遗漏。
- **段缺失 ≠ 段为空**：`sections` 记录"文件里真的出现过哪几段"，
  缺失的段在导入时**保持用户现有设置不动**。这是"导入绝不删东西"的技术保证 ——
  没有它，一份 v1 老文件就能把用户的标记与区域类型定义清空。
  （⚠️ 见 §5.29：这道守卫在当前实现下**不可观测**，真正在保护的是"空数组 + 合并只增不删"。）
- **同 ID 冲突保留用户现有的定义**（导入是"补充"，不是"替换"）；冲突会记进"跳过 N 条"并给出原因。
- **幂等**：刚导出的文件立刻再导入 = **0 新增**，设置逐字段不变。
- **版本策略**：`version` 停在 2（v2 是本周期内引入、尚未发布给用户的格式，
  加 `regionTypes` 时不再凭空升到 3）。解析**接受 1 与 2**；**比支持版本更高则明确拒绝**
  并提示升级插件 —— "尽力解析"等于骗用户说导入成功了。
- **解析、计划、落盘是同一份计算**：确认对话框里说的"会发生什么"（`planBundleImport`）
  就是真正落盘用的那份计划，所以"对话框说的"与"实际做的"不可能不一致。
- 空文件（一段都没有）在解析侧就被拒绝；没有可导出内容时**干脆不写文件**
  （写一个空文件只会让用户以为导出成功了）。

## 5. 已经踩过的坑（**请务必先读这一节**）

这一节是本项目最贵的资产。前五条都表现为"测试全绿、功能却是坏的"。

### 5.1 坐标：不要用 `tx/ty` 推，用量出来的锚点投影

`posFromEvt` 的输出被**量化到 1 CSS 像素**（实测量子 = 1.000001 CSS px，与 dpr 无关），
噪声上界 `q·√2/2 ≈ 0.707 px`。旧版"视口中心 = (tx, ty)"的公式在真实数据上有**恒定平移误差**。
现在一律走 `buildProjection()`（锚点 + 矩阵缩放反解），误差在半个量子内。
不要在运行时施加"偏差修正"：实测偏差在噪声内，加了反而引入未经验证的偏移。

### 5.2 覆盖层插在宿主**第一个**子元素 ⇒ 它永远收不到指针事件

绘制顺序 = 命中测试顺序。地形要画在卡片下面，就必须插在最前，于是覆盖层在最底层。
**结论**：覆盖层永久 `pointer-events: none`；绘制手势在 `view.containerEl` 上以**捕获阶段**监听
（`preventDefault + stopPropagation + stopImmediatePropagation + setPointerCapture`），
并且**必须排除同一容器里的 UI**（工具条、`.canvas-controls`、`.canvas-card-menu`）。

### 5.3 ⚠️ `ctx.font` 里不能写 `var()`

```ts
ctx.font = `600 24px var(--font-interface, sans-serif)`   // ❌ 整条声明非法
```

canvas 的 `font` 是 CSS `font` 简写，`var()` 没有元素上下文可供替换 → **非法赋值被静默忽略**，
画布继续用上一个字体（初值是默认的 `10px sans-serif`）。症状极具迷惑性：
**只有线宽（普通数值属性）会变，字号永远不变**。

修法（`shapeDraw.ts`）：① 字体族用 `getComputedStyle(el).fontFamily` 取**已解析**的列表；
② 赋值后**读回校验**字号，不符就退到 `sans-serif` 重写一次。

**推广**：任何"静默失败的 API"（无效赋值被忽略、不抛错）都必须**读回校验**。

### 5.4 位图 ↔ CSS 像素比例要**实测**，不要假设等于 `devicePixelRatio`

`MapOverlay.measureRasterScale()` 用 `canvas.width / getBoundingClientRect().width` 实测。
名称字号承诺的是"N 个 CSS 像素"，那就必须以浏览器实测为准。
冒烟里有一条对抗性断言：把屏幕尺寸量成一半，字号必须翻倍。

### 5.5 断言要断言**几何**，不要断言"调用了几次某个 API"

出过三次事故：

| 旧断言 | 实际测的 | 漏掉的 |
|---|---|---|
| `calls.bezierCurveTo > 0` | 预览用了贝塞尔 | 提交后走的是另一条分支（**河流变折线**） |
| `calls.stroke >= 2` | 逐段描边了 | 每段的端点用的是控制顶点 → 折线 |
| `calls.fillText === 2` | 画了两次文字 | 改逐字排版后这个数字失去意义 |

现在冒烟桩会记录**每个路径段的实际坐标**与**每个字形的实际位置/旋转角/字号**，
断言改用最大转角、弧长间距、CSS 字号等几何性质。
**自检方法**：把新断言跑在修复前的产物上；如果它照样通过，就防不住这个缺陷。

### 5.6 ⚠️ 六边形顶点图：**3 个邻居，且方向不固定**

做"沿格边"（勾勒六边形边框）时踩到的两个反直觉之处，都是被单元测试当场抓住的：

1. **每个顶点只有 3 个邻居**，不是 6。顶点与边构成的图是**蜂窝图**（3-正则）。
   "距离等于边长的 6 个方向"里，有 3 个指向的是相邻六边形的**中心** ——
   因为正六边形里顶点到中心的距离**恰好等于边长**。
2. **方向不固定**。蜂窝图是**二分图**，相邻顶点分属两个子格，两组顶点的边方向相差 60°
   （pointy 下是 `{90,210,330}` 与 `{30,150,270}`）。所以"按固定角度算邻居"对一半顶点是错的，
   会指到格心上去。

结论：**不要手推角度，用自验证的写法** —— 把 6 个候选方向都算出来，
只保留"吸附回自身"的那些（格点吸附后仍在原地，格心会偏出半个边长）。
代价是每次查询多几次吸附计算，换来的是对任意方向、任意子格都成立。
单元测试覆盖了两种朝向 × 100+ 个顶点，正是它抓住了上面两条。

推论：沿格边的两点之间需要"多走再抵消"，**路径最坏约为直线距离的 2 倍**
（三条格边方向相隔 120°，不是正交格那样的 √2）。

### 5.7 其他已固化的小坑（细节见 `docs/PHASE-1-NOTES.md`）

- `-0` 与 `0` 是不同的 Map key（格坐标）→ 统一 `normalizeZero`。
- `{ ...null }` 是 `{}` 而不是 `null`（会污染撤销栈）→ 必须显式判空。
- 自写保存会触发 `modify` 事件 → 用 **mtime** 区分自写与外部改动（**不要用时间窗**，
  会吞掉紧随其后的真实外部改动）；重载**不得清空撤销历史**（op 记的是"格 + 新旧状态"）。
- 无修饰键的快捷键（`D/B/M/T/P/R/1-9/[]`）必须**自己让行给输入框**：Obsidian 的 Modal 只注册
  自己用到的键，其余会落到画布作用域（处理时返回 `true` = 未处理，`false` = 已消费，别写反）。
- 变宽描边只能**逐段 `stroke()`**（canvas 的 `lineWidth` 是整条路径统一的），因此必须先展平曲线；
  展平采样数有上限（`FLATTEN_MAX_SEGMENTS`）。**河流很多时帧率需要实测**。
- DOM 标记层容器**始终 `pointer-events: none`**，只有实体加 `.is-interactive`，否则挡住原生框选。
- 名称锚点：路径用**按弧长的中点**（不是"中间那个顶点"），区域用**面积质心**
  （凹多边形质心落到形状外时退化为形状内最近点）。
- **草稿必须存"走出来的整条边路"**，不能只存吸附后的端点：只存端点的话预览里那一段还是直线、
  提交后才变成格边 —— 又是一次"所见非所得"（这个项目已经犯过两次同类错误）。
- 路径/区域的几何模式：`interior`（穿过格子内部）/ `edge`（沿格边）。
  `edge` 模式下**不做平滑**（平滑会把格边抹成曲线），并保留末端变细与虚线。
- 命中测试要用**可见几何**（`visiblePolyline`）而不是控制顶点，否则急转弯处"点在线上了却删不掉"。
- 异步加载必须**显式发起**并留下可观测结果（Base 视图曾经忘了触发地图文档加载，
  表现是"地图条目永远是 0"而界面无任何报错）。

### 5.8 改名要分清"显示名"和"持久化标识"

插件 ID 已经改成 `project-kaki`（`deploy.mjs` 负责迁移旧目录），但下面三个字符串**永远不要改**，
它们不在插件目录里，而是写在用户的文件和 Obsidian 的工作区布局里：

| 标识 | 写在哪 | 改了会怎样 |
|---|---|---|
| `fictional-cartographer-map`（`MAP_FILE_TYPE`） | 每张地图 `.map.md` 的 frontmatter `type:` | 已有地图全部认不出来（会被当成普通笔记，且插件拒绝写回） |
| `fictional-map`（`BASES_VIEW_TYPE`） | 用户 `.base` 文件里的 `views[].type` | 已保存的 Base 视图变成空白/报错 |
| `fictional-cartographer-panel`（`MAP_PANEL_VIEW_TYPE`） | `.obsidian/workspace.json` 里已打开的标签页 | 侧栏里已打开的面板失效 |

判断标准很简单：**标识出现在用户文件里 → 不动；只出现在插件自己的注册调用里 → 可以改**。
真要改就必须同时提供迁移（读取旧值并改写用户文件），否则对用户就是数据损坏。

### 5.9 侧边栏"卡"：别把每帧都在变的值放进"要不要重绘"的判断里

面板用「顶部状态 + 每个动作的可用性」拼成一个**签名**，签名不变就跳过重绘（`MapPanel.ts`）。
第一版签名里放了"当前视口画了多少格地形"——平移画布时这个数字每帧都变，
于是面板跟着**每帧重建 DOM**，表现就是侧栏发卡。凡是"每帧都可能变"的数字（可见格数、坐标、帧率）
都不要进签名，需要的实时数字放到命令的输出里看。

同类的坑：`contentEl.childElementCount > 0` 这类"DOM 内省"判断在假 DOM 里可能是 `undefined`
（`undefined > 0` 恒为假），于是"跳过重绘"静默失效；用**自己的布尔标记**（`rendered`）更可靠。

### 5.10 样式设置：把"用户输入"与"文件里的数据"分开

做「自定义路径/区域颜色、字体」（`stylePalette.ts`）时定了两条边界，都不是技术限制而是**语义选择**：

1. **设置只影响新画的对象**。路径与区域各自把颜色存在地图文件里（`path.color` / `region.color`），
   渲染时用文件里的值。若让设置去覆盖渲染，用户改一次颜色就会"历史地图全部变色"，
   而且**无法撤销**（撤销栈记的是编辑动作，不记设置）。所以改色是"改默认值"，不是"全局滤镜"。
2. **区域颜色存"预设下标"而不是色值**（`MapEditor.regionPresetIndex`）。
   存色值的话，用户在设置里换了调色板之后，编辑器手里还攥着一个已经过期的旧色，
   下一次画区域会用旧色 —— 又一个"看起来生效了其实没有"。存下标则天然跟随。

`normalizeColor` / `normalizeFontFamily` 这两个纯函数值得单独一测，因为：

- 非法颜色到了 canvas 上是**静默忽略**（该次 fill 沿用上一个颜色，画出来就是错的颜色）；
- 字体串更狠：整条 CSS font 简写（`600 24px sans-serif`）被当成字体族拼进 `ctx.font` 之后，
  整条声明非法、被静默丢弃 → 字号退回默认 10 px，正是 §5.3 那个坑的另一种进门方式。
  **这条是单元测试当场抓到的**：我第一版的过滤只挡 `var()`／斜杠／括号，
  `600 24px sans-serif` 能顺着"只含字母数字空格"这条规则溜过去。

### 5.11 自定义地形（②）逼出来的三条教训

1. **"未知值"要分清"数据保全"与"显示偏好"**。
   `parseTerrain` 原来把无法辨认的 `t` **丢弃**（报"已跳过该格"）—— 用户只要保存一次，
   自己的数据就被永久删掉了，而插件没有权利替用户判断"这个 ID 没用了"。
   现在改为**接受并告警**（"已保留该格"）：只有完全不可能当 ID 的值（非字符串／空串／控制符／超长）才跳过。
   判据很简单：**未知的东西属于用户的数据，不属于我们的显示偏好**。
2. **图集必须覆盖"文档里出现过的每一个 ID"，而不只是"设置里定义的那些"**。
   漏掉未知 ID 的后果不是"颜色不对"，而是找不到精灵、**那一格根本不画** ——
   用户看到的是地图上有个洞。**"静默少画"比"画得不对"难查得多**：前者没有任何线索。
3. **缓存键选错的表现是"静默不生效"**。
   自定义地形的图片一开始按"地形 ID"缓存：换图后永远画旧的那张、两个地形共用一张图时第二个永远加载不到。
   改成按**图片路径**缓存后又出现半途改动留下的键不匹配 —— **存按 path、取按 id**，
   于是图集永远拿不到图，画布上一直显示回退色，而日志里只有一句"图片不可用"。
   只有断言到**"画的是哪张图"**（`drawImage` 的 source 就是加载到的那幅图）才抓得住这类错误。

   这 4 条断言在修复前**实测失败**、修复后通过 —— 这就是"鉴别力"的实证。
   写完断言顺手在旧实现（或人工破坏的状态）上跑一遍，比读十遍代码可靠。

另外两个"数字上的决定"也记在这里：自定义地形**上限 40 而不是 64**（图集是一行位图，每条一列 260 px；
64 条时宽度≈1.9 万 px，超过部分平台 16384 的画布上限，超了会**静默不显示**），
以及**不占用数字键 1–9**（键位已被内置占满，再抢会破坏既有肌肉记忆）。

### 5.12 同一件事只能有一个真相（③ 图层开关时付的代价）

做图层开关时，名称可见性一度有**两份状态**：`MapEditor.showShapeLabels`（每张画布的运行时状态）
与设置里的 `layers.labels`（持久化）。两份状态必然出现无法解释的组合：
"设置里开着、工具条显示关着""重开画布后按钮与设置不一致"。

落点（已按此清理，**不要再加回来**）：

- **可见性状态只放插件设置**（`CartographerSettings.layers`）；画布侧一律**每帧现读**
  （`isLayerVisible(this.layers(), 'grid' | 'labels')`），不存副本；
- 已删除：`MapEditor.showShapeLabels` 字段与其 setter、`EditorStatus.showShapeLabels`、
  `MapOverlay.showGrid` 与其 setter、`MapLayerManager` 里"镜像给编辑器"的两步、
  `main.ts` 的 `setShowGrid`、`CartographerSettings.showGrid` 字段
  （`data.json` 里的旧 `showGrid` 只作为**迁移输入**读一次，新写入不再包含它）；
- 工具条的回调（`onToggleLabels` / `getShowShapeLabels` / `getShowLegend` / `onToggleLegend`）
  改成**必填**：之前它们可选、还留了一条"没回调就改编辑器字段"的兜底 ——
  那正是"点了没反应 / 改了别处"的温床。**让错误在编译期出现，而不是在用户手里**。

**鉴别力实测**：把 `getShowShapeLabels` 临时改成 `() => true`（模拟"按钮读另一份状态"）→
恰好 3 条相关断言失败、其余 511 条保持绿；改回去后全绿。新增的两条回归断言专门盯这件事：
`layers.disable()` 之后再挂载（换出全新工具条）时，按钮必须显示**设置里的**状态。

顺带一条通用教训：用 `pwsh` 跑内联脚本时，**双引号与反引号都是元字符**，
含它们的字符串会被静默改写（我因此两次写出"看起来跑了、其实模式没匹配上"的命令，
一次让 git 提交失败、一次让文档替换静默失效）。复杂文本一律用编辑工具改。

### 5.13 两个"静默变形"的陷阱（④ PNG 导出与设置测试时抓到的）

1. **归一化会把"空值"夹成"下限"，而这两者语义完全不同**。
   `normalizeLabelScale(null)` 曾经返回 **0.5**（下限）—— 因为 `Number(null) === 0`，
   于是 `Math.max(0.5, 0)` 把它顶到了下限。手工把 `data.json` 写成 `"labelScale": null` 的用户
   会看到字号莫名其妙变成最小，而且没有任何提示。判据：**"没填" ≠ "填了一个下限值"**；
   现在只有 `number` 或非空字符串才算"用户真的给了值"，`null` / `''` / `[]` / `true` 一律回默认。
   （这条是新增的 `tests/settings.test.ts` 当场抓到的 —— 之前 `normalizeSettings` 一条单测都没有，
   因为它住在 `import 'obsidian'` 的 `SettingsTab.ts` 里，而 ESM 单测 import 不进来。）
2. **假 DOM 的两种失真会让"要覆盖的分支"永远走不到**：
   - `document.createElement('img')` 若返回通用元素、没有 `complete`/`onload` 语义，
     "等待图片加载"会**永远不返回**（真实的浏览器要么命中缓存、要么触发 load）；
   - 桩不认 `data:` URL 时，PNG 导出会在"图片解码"那一步先失败，
     真正想覆盖的 **`toBlob` 降级分支永远走不到** —— 测试全绿，但覆盖是假的。

   这正是 §5.9 那条的另一种形态：**桩少一个成员，被测逻辑就会静默走另一条分支**。
   补桩时要照着真实语义补（"如实"，而不是"能跑就行"），并且**刻意留一个不支持的能力**
   （例如假画布就是不给 `toBlob`）来覆盖降级路径。

### 5.14 一个能把自己弄没的按钮，不适合承担"关掉自己"的职责

工具条上原来有个「地图层」按钮：文案是 `地图层`、提示是"停用当前地图层"，
点了会把整个地图层关掉（地形消失，**连工具条自己一起收起来**）。用户的反馈是
"不知道是干什么的" —— 这句话同时指出两件事：**文案没表达出后果**，
而且**这个位置本身就不对**。

判断规则（值得记住）：**如果某个入口会让自己消失，它就不能是唯一入口**。
停用地图层现在只保留两个入口：侧栏的地图面板（常驻，与地图层存亡无关）与命令面板。
冒烟里专门加了回归断言：关掉地图层之后，**面板仍在、并且能把它开回来**。

顺带一条 UI 口径：面板里的六个图层开关与设置页的开关**共用同一份设置**，
面板只拿 `getLayerVisibility` / `onToggleLayer` 两个**必填**依赖（不是可选 + 兜底）——
"忘了接线"会在编译期报错，而不是变成一个点了没反应的按钮（§5.12 同一思路）。

### 5.15 又一次"期望值写错"：自检会把正确行为判成失败

给图层开关补冒烟断言时，我写的是 `layers.listStatus()[0]?.attached === false` ——
而停用地图层后那个画布会被从"已启用"集合里**移除**，于是 `listStatus()` 返回**空数组**：
`[0]` 是 `undefined`，断言失败；但旁边那条（"工具条确实随地图层一起消失了"）是**通过**的 ——
说明实现没问题，是我的期望值错了。

这是同一类错误的第二次（`scripts/release.mjs` 里也犯过一次：拿 `versions.json` 的值去比版本号）。
判据必须从**实现的真实返回形状**来，而不是从我脑子里的形状来。
**一个期望值写错的自检，比没有自检更坏** —— 它会把正确的行为拦下来，然后让人去"修"一个没坏的东西。

### 5.16 长文本不该用 Notice 承载（用户又一次说到了点子上）

状态报告原本是 `new Notice(多行文本, 15000)`。用户的反馈是：
"**遮挡侧边栏的按钮，过一会才消失，等待时间过久，要不直接做成可导出的调试模式内容？**"

三条判据（超出任意一条就该换载体）：

1. **位置**：Notice 出现在右上角 —— 正是侧边栏按钮区；一条要读十几秒的提示等于把用户的操作区按住不放。
2. **时长与需求不匹配**："回头再查"的信息（统计、字号、标定、图层、图例）需要**一直拿得到**，
   而 Notice 是"一闪而过"的载体。用短时长会读不完，用长时长会挡人 —— 两头都不对。
3. **拿不出来**：Notice 里的文字**选不中、复制不了**。凡是用户可能想贴给别人看的内容，
   都必须落在能复制的载体里（现在是报告面板的 `<pre>`，可复制、可导出成库内文件）。

落点：

- `Notice` 时长上界 `NOTICE_MAX_MS = 6000`（**唯一来源**，35 处引用）；
  需要更长时间的阅读内容一律进报告面板，而不是把数字调大。
- 冒烟里有一条**全局断言**：任何命令跑完之后都不允许存在 >6000ms 的提示。
  它的鉴别力是实测过的 —— 把上界改回 15000，这条会立刻点名三条超时提示并失败。
- 报告面板**不认识 vault**：写文件靠注入的 `onExport`。于是面板本身可以在没有 Obsidian 的环境里被构造与断言
  （与 `MapLegend`、`viewContract` 同一个思路）。

另外记一条这次暴露出来的测试坑：**假 `Modal.open()` 太薄时，真实对话框的 `onOpen` 在冒烟里从未被执行过** ——
把桩改忠实之后，立刻暴露出假 `Setting` 缺 `setCta` / `inputEl`、假元素缺 `focus()`
（见 §5.13 第 2 条：桩少一个成员，被测逻辑就会静默走另一条分支）。

### 5.17 「先 build 再 smoke」现在已经由脚本强制（这条陷阱发作过两次）

冒烟测试加载的是打包产物 `main.js`。改了源码不重新构建，跑的就是**旧产物**。这条陷阱已发作两次：

第一次是新场景全红，症状像"新断言写错了"；第二次更糟：冒烟失败后，实施者据此
**推断出"异常被 `void` 吞掉了"**，还照着这个推断加了 `.catch()`。真正的原因是没重新构建。
`.catch()` 留着是对的（重绘失败不该静默），但它**不是**那次失败的解药 ——
**基于错误前提的修复比不修更危险**，因为它会让人以为问题已经解决。

**结论：能被自动化拦住的错误，就不该只写在文档里。** 现在
`scripts/lib/bundleFreshness.mjs` 提供一个共享门禁，`smoke.mjs` 与 `deploy.mjs` 都在启动时调用它：

- 产物**不存在** → 打印"还没有构建产物：请先跑 `node scripts/build.mjs`"并**以非 0 退出**；
- 产物比 `src/` 下任何文件**旧** → 打印两个时间戳作为证据并**以非 0 退出**；
- **没有"警告后继续"的开关**：警告后继续等于没拦，而这里要防的正是"人看到警告仍然继续"。

鉴别力是**实测**的（不是推理的）：

| 情况 | 结果 |
|---|---|
| `touch src/main.ts`（只改 mtime） | 退出码 1，打印"最新源码 … / 产物 …"两个时间戳 ✓ |
| 挪走 `main.js` | 退出码 1，打印"还没有构建产物…" ✓ |
| `node scripts/build.mjs` 后再跑 | 退出码 0，冒烟通过 ✓ |

**部署侧更值得拦**：`deploy.mjs` 若复制一份旧产物，用户会在真实 Obsidian 里验证**过期的代码**，
而且他无从知道 —— 界面是真的、结论是错的。所以 deploy 也走同一道门禁（提示语按动作定制）。

CI 不受影响：两个工作流里 `build` 都在 `smoke` 之前（`.build/verify-workflows.mjs` 也断言了这一点），
干净 clone 每次都先构建，门禁必然通过。

### 5.18 同一份白名单只能有一处（"选得出却被拒"的自相矛盾）

做"从库里选图片"时，选择器要列出可用图片、校验要拒绝非法路径 —— 两处都依赖扩展名白名单。
各写一份的后果是最难受的一种体验：**弹窗里列得出来、选中却被拒**（或反之）。
落点：`terrainCatalog.IMAGE_EXTENSIONS` 改为 export，选择器与校验都 import 它，
并加一条**防回归断言**：遍历每一种扩展名，`isImagePath()` 与 `checkTerrainImagePath()` 的判断必须一致。

这与 §5.11 的"图集必须与导出共用一份解析"、以及调色板曾经分叉那次是同一类问题：
**凡是"两处各自判断同一个东西"的地方，迟早会分叉。**

### 5.19 别用"目测"代替"读汇总行"

项目的测试基线曾在文档里被写成 278，而实测是 **273**。原因很朴素：
CI/README 里用的是 dot reporter（一行 20 个点），而我**用点数的行数去估总数**。
正确做法只有一个：读默认 reporter 打印的汇总行 `ℹ tests 273`，或者让脚本自己打印断言数
（`smoke.mjs` 就是这么做的）。**能被读出来的数字，不要靠数。**

### 5.20 模式要显式存在，不要靠"有图就用图"推断

自定义地形最初把颜色与图片两个字段并排摆着，画什么靠**隐含规则**（有图片画图片，否则画颜色 + 字形）。
用户的反馈是要求"两个模式，做成 UI" —— 一针见血：隐含规则让用户**看不出自己处于哪种状态**，
也看不出"两个都填会怎样"。

落点：`CustomTerrain.mode: 'color' | 'image'` 显式存进设置，UI 上是一个两选一的分段控件，
不同模式只显示该模式需要的字段（图片模式下颜色降级为"加载失败时的回退色"，说明文字也照实改）。

一个容易做错的细节：**非法模式值不要静默降级成默认模式**。若把无法识别的 `mode` 当成 `'color'`，
"配了图却不显示"就会变成界面上一切正常的问题；正确做法是与"缺失"走同一条**推断**
（`imagePath` 非空 → `image`），于是老用户升级后画面与升级前完全一致。

### 5.21 当前模式下用不到的字段要**保留**，只是不显示

"调色模式不显示图片栏"很容易顺手写成"切到调色就把图片路径清掉" —— 那是**静默删用户数据**：
用户来回切一次模式，之前选好的图片就没了。落点是：切换只改 `mode` 一个字段，
另一个模式的取值原样留在设置里，切回来还在。只有"删除这条定义"才是真的丢数据。

同理，导出成定义文件时必须带上 `mode`：否则"图片模式下配好的图"导入到别处会被推断成调色模式，
看起来像导入失败。

### 5.22 UI 改结构会连带打破"按文案查找"的测试选择器

把一条设置的标题从「字形与图片 · X」拆成「名称与颜色 · X」/「字形 · X」/「图片 · X」之后，
两个既有冒烟场景当场失败 —— 它们是按**文案**找控件的。这不是桩的问题，而是测试与 UI 文案耦合的必然结果。

处理办法（本项目现在这么做）：**凡是测试要点的控件，尽量给稳定的 `dataset` 标记**
（例如模式的 `data-mode`、图层开关的 `data-layer`），文案只用于显示；
实在要按文案找，就把查找封装成一个辅助函数，UI 改名时只改一处。

### 5.23 「整片一张图」：连通性是语义的一部分，不是实现细节

用户要的是"**连通的**同类型格共用一张图"。第一反应会想用**包围盒**分组（简单、少一次遍历），
但那是错的：两片隔着一条海的地形会被算成一块，图片横跨中间那片不属于它的区域，
裁掉之后**两片各自只剩残缺的一角**。邻接才是"同一片"的定义 —— 这里的连通性不是实现细节，是需求本身。

配套的三条决定：

- **分组取自整个文档，而不是视口裁剪后的格子**。若按 `plan.cells`（只含视口内的格）分组，
  平移到边缘时连通块会被切断、整片图的尺寸跟着缩水 —— 表现是"平移画布时图片突然变小"。
  所以分组用 `document.terrain`，而 `clip()` 路径只用**可见格**构建（裁剪是为了少画，不是为了少算）。
- **整片图不能走精灵图集**：图集是按格切片的位图，跨格取图根本取不到。
  于是它走独立的 `save → 六边形并集路径 → clip → drawImage(contain) → restore` 路径；
  也正因为图集是"一行 N 列"的位图，`MAX_CUSTOM_TERRAINS` 当初才从 64 降到 40。
- **保比例用 contain，且图片尺寸非法时退化为铺满**：0 尺寸的 `drawImage` 在画布上是**静默不画**，
  用户只会看到"这一片没图"，所以宁可退化也不要画出 0 尺寸的东西。

### 5.24 「空转断言」：在坏实现下也能通过的断言等于没有断言

写"整片图平移到边缘后尺寸不变"这条断言时，实施者**试了三版几何**才让它成立：

1. 让林带比视口宽 → **空转**：坏实现下可见子集本来就被视口截断，两块尺寸一样大；
2. 15 格、平移 +300 → **仍然空转**：基线时林带已经越出右边界；
3. 最终版（`q ∈ [-12, 2]`、`r = 3`：基线时整条可见，平移后丢掉左端）才有效 ——
   用**坏实现**（改成按 `plan.cells` 分组）验证，结果**精确地只错这一条**：

   ```
   ✖ 平移之后整片图片的尺寸不变 — 平移前 78.6×59.0 → 平移后 51.1×38.3
   ✔ 平移确实改变了它在画面上的位置（否则上面的断言没有鉴别力）
   ```

**规矩**：新写一条断言时，先把它跑在**坏实现**上（或临时破坏实现），确认它真的会失败。
这与 §5.5「断言要断言几何」是同一件事的两面：那边管"断言什么"，这里管"断言有没有用"。
配套技巧：在关键断言旁边放一条**前提断言**（如"平移确实改变了位置"），
这样几何设置再次失效时，红线会指出是前提没成立，而不是让人怀疑实现。

### 5.25 「导出选范围」的三条

1. **范围 = 改「世界 → 像素」的映射，不做内容裁剪。**
   范围只影响 `viewBox` 与画布尺寸：落在范围外的内容**照旧全部绘制**，由 SVG 的视口自然裁掉。
   这样做的理由是"少一套几何判断，就少一处出错的地方" —— 自己写裁剪意味着要处理路径/区域/文字
   与矩形相交的各种情况，而平台已经在做这件事了，且做得对。
   （对用户也要说清楚：**按范围导出不是丢内容**，换回"全部内容"它们都在。）
2. **0 跨度必须在入口挡住。**
   `spanX || 1` 这种写法会把内容放大到荒谬比例，而导出**仍然"成功"**（生成一张怪图，
   用户不会怀疑是范围算错了）。所以有显式的下限 `MIN_EXPORT_SPAN`：
   把"退化的范围"变成**可读的拒绝**，而不是一张看起来正常、其实荒唐的图。
3. **假 DOM 少一个成员不会报错，只会静默改变行为。**
   这次是假 `addDropdown` 缺 `selectEl`，于是 `dataset` 标记无处可挂 →
   断言永远找不到控件，表现为"界面没渲染"。与 §5.13 完全同源：
   **桩少一个成员，被测逻辑就会静默走另一条分支**；补桩时要照着真实语义补。

   顺带记一条**实施者自己发现并修掉的接线缺陷**：失败时对话框原来会被关掉，
   而那正是"PNG 不可用、最该提示改用 SVG"的时刻 —— 关掉窗口等于把用户丢在原地。
   现在失败**留在原地**，并且提示**只发一次**（由导出实现统一发，对话框不再重复说）。

### 5.26 自定义标记图标（④）的两条：白名单会改坏数据、空转断言

**教训一 · 白名单会把用户数据改坏**

**现象**：`markers[].icon` 原本按内置 9 种做白名单校验，认不出的名字一律被替换成 `town`。
于是"别的库、别的版本、或用户手写进去的图标名"在**打开、显示、导出时全部正常**，
用户不会怀疑任何东西 —— 但他**一保存**，文件里的图标就被永久改写成了 `town`。
等到用户发现"我的图标怎么全变成村镇了"时，原来那个值在磁盘上已经不存在了；
地图文档是纯文本，进了 Git 还能从历史里翻回来，没进 Git 就是彻底丢了。

**根因**：把"能画出什么"和"文件里能存什么"当成了同一件事。解析层只负责读，
它**没有权利替用户判断"这个图标名没用了"** —— 那是显示偏好，不是数据。
判据与 §5.11 第 1 条（未知地形 `t` 曾被丢弃）逐字相同：**未知的东西属于用户的数据，
不属于我们的显示偏好**。这两次是同一口径的两次应用，将来还会有第三次。

**修法**：

- `MarkerId` 从字面量联合放宽成 `string`（与 `TerrainId` 完全同构），
  解析只校验**存储形状**（`isStorableMarkerId`：非字符串／空串／含空白与控制符／超过 64 字符才拒绝），
  未知图标**原样返回**并推一条 `warning`：`未知图标 "lighthouse"，已保留（按回退样式绘制；内置图标：…）`；
- 告警**只对"既非内置、又不在 `custom:` 命名空间"的值**发：解析层读不到用户设置，
  无权判断某个 `custom:xxx` 是否已经定义；
- 回退视觉整体交给绘制层：`resolveMarkerStyle` **永不返回 null**（内置 → 自定义 → 未知），
  未知 ID 画成回退图钉（`FALLBACK_MARKER_ICON_NAME = 'circle-dot'`）并带上 `unknown: true`；
- 只有"根本不是合法字符串"才回退成 `town`，而且原因与"未知图标"**分开写**（两件事，别写成一句话）。

**如何防止复发**：凡是"解析 → 序列化"会往返的字段，先问一句
**"认不出时我是保留，还是改写／丢弃？"**；答案永远是保留 + 告警。
落点是两条断言：`tests/mapDocument.test.ts` 的"外来图标往返后一个都没变"，
以及冒烟场景 33 的"重新解析后图标一个都没变（这轮往返就是'保存会不会删数据'的答案）"。
**鉴别力是实测的**：把未知图标改回"替换成 `town`"，这两条立刻变红。

**教训二 · 空转断言：在坏实现下也能通过的断言等于没有断言**

**现象**：`tests/markerCatalog.test.ts` 里"签名的任一字段变化都要变"那条断言，
最初写的是拿**单条**的签名去比**两条**（`SAMPLE`）的签名。它一直是绿的 ——
但把 `mode` 从 `markerCatalogSignature()` 里删掉，它**照样绿**：因为"元素个数不同"
本身就足以让 `notEqual` 成立，它测的是"两条签名不同"，而不是"这个字段改了签名就变"。

**根因**：断言的两边差的**不止一个变量**。这与 §5.24 是同一类问题 ——
那里是"几何设置不成立"，这里是"比较对象不成立"，共同点都是
**断言在坏实现下也通过**，于是它对实现没有任何约束力。

**修法**：单条对单条（`const signature = (marker) => markerCatalogSignature([marker])`），
并且每条断言**只差一个字段**（`id` / `label` / `icon` / `imagePath` / `mode` 各一条），
再补一条"内容相同必须给同样的签名"（否则每次刷新都会重建工具条 DOM）。

**如何防止复发**：照 §5.24 的规矩办 —— 新断言先跑在**坏实现**上。
这次的做法具体到可照抄：把要保护的字段从实现里删掉，看这条断言是否变红。
删掉 `mode` 后仍然全绿 ⇒ 判定为空转 ⇒ 改成单条对单条 ⇒ 再删 `mode`，立刻红。
配套一条本轮的通用做法：这一轮的四个改动点（未知图标改写、忽略模式、签名去掉 `mode`、
去掉坏图重试闸门）**每一个都先在坏实现上验证过鉴别力**，而不是写完就宣布通过。

### 5.27 把"类型联合"收窄成内置集合，让查表在编译期就过不去

**现象**：路径的 `type` 原本是字面量联合 `'river' | 'road' | 'trade-route' | 'border'`。
解析时先判断"它在不在 `PATH_TYPES` 里"，不在就把 `type` 置 `null`，紧接着
`if (id === null || type === null || pts === null) return null` —— **整条路径被跳过**。
后果比 §5.26 的标记图标那次更重：那次是"一个字段被改写成别的值"，这次是
**整个对象从文档里消失**。用户拿到别的库（或别的版本、或手写）写下的自定义路径类型地图，
**打开一次、保存一次，那条路就永久没了**，而且只留一条把"类型不认识"与"坐标坏了"
混在一起的 warning（`路径缺少 id / 合法 type / 至少两个有效点，已跳过`），
从这条提示里根本推不出"我有一条路要消失了"。

**根因**：`PathType` 是字面量联合 ⇒ `PATH_TYPES.includes(...)` 这种判断**必须**由人记得写，
而"忘记写"的默认结果是丢弃。写完 `PATH_STYLES[type]` 这类"出厂表"查询时，
类型系统看起来是"安全"的（键都在联合里），于是**"未知值"这条路径根本没有被表达出来** ——
它被 `null` 悄悄吃掉了。

**修法**（三步，缺一不可）：

1. `PathType` 放宽成 `string`（与 `TerrainId` / `MarkerId` 同构），**内置那 4 个**收窄成新的
   `BuiltinPathType`；于是 `PATH_STYLES: Record<BuiltinPathType, PathStyle>` 仍然只有 4 个键 ——
   **"拿未知 ID 去查这张表"在编译期就过不去**，必须显式走 `resolvePathType()` 那条回退路径。
   也就是说：不安全的那件事不再是"默认会发生"，而是"写不出来"。
2. 解析层只判断**存储形状**（`isStorablePathTypeId`：非字符串 / 空串 / 含空白或控制符 / 超 64 字符），
   认不出的 ID **原样返回** + 一条 `未知路径类型 "spaceship-lane"，已保留（按回退样式绘制；…）`；
   **只有"完全不可能当 ID"的值**才回退成 `river`，而且**回退也不丢路径**。
3. 回退视觉整体交给绘制层：`resolvePathType()` **永不返回空**（内置 → 自定义 → 未知）。
   区域类型（⑤-2）复用同一套：`readRegionType()` 同样保留 + 告警，
   且**"类型有问题"绝不导致区域被丢弃**（`mapDocument.ts` 的注释把这条写成了硬约束）。

**如何防止复发**：看到一个"字面量联合 + `includes` 判断"的组合，先问
**"认不出时会发生什么？"**，再问 **"这个默认行为安全吗？"**。
安全默认的判据只有一条：**未知值必须能原样往返**（§5.11 / §5.26 同口径）。
落点是两条断言：单测"未知路径类型**保留整条路径**"、冒烟场景 34 的
"打开时还在文档里 / 落盘后文件里仍有 / 重新解析一条都没少"。
**鉴别力是实测的**：把未知 `type` 改回"不认识就丢整条路径"，1 条单测 + 6 条冒烟断言立刻变红。

### 5.28 假 DOM 不模拟事件传播 ⇒ 断言空转（"点画布收起下拉"那一击到底打中了谁）

**现象**：工具条的类型下拉展开时，用户点画布上的任意位置应当**只**把下拉收起来。
原实现的监听只做了一件事（关下拉），**没有拦下这一击**；而它对应的冒烟断言是这么写的：

```js
fakeDocument.dispatchEvent({ type: 'pointerdown', target: wrapper })
check('点在画布上（下拉外面）时下拉收起 —— 否则那一击会顺手在地图上画一个点', …)
```

问题有两层：
1. 这条断言只在 `document` 上派发事件，而**假 DOM 不实现事件传播** ——
   它根本到不了画布的监听器，所以"画布会不会收到这一击"从来没有被检查过；
2. 断言检查的只是"下拉收起了没有"，**而工具条什么都不做时这一条也是绿的**。
于是注释里明明写着"否则那一击会顺手在地图上画一个点"，却**没有任何东西在检查这件事**。
实际后果：用户在路径模式下刚选完类型，点一下画布想收起下拉，就**顺手多出一个路径顶点**
（一笔他没想画、还得撤销的东西）。

**根因**：桩的能力边界被当成了"契约已经验证"。假 DOM 缺的每一项能力，
都会让依赖它的断言悄悄退化成空转（§5.24）—— 这次缺的是**事件传播**。

**修法**：

- 新增 `firePointerThroughDocument(documentNode, canvasHost, init)`：按真实顺序走两跳
  （`document` 的捕获阶段 → 画布容器），并尊重 `stopPropagation()`；
  返回值里的 `reachedCanvas` 就是"这一击有没有到达画布"的客观记录，断言直接看它；
- 工具条侧在关下拉之后 `event.stopPropagation()`（只影响"下拉正展开"的这一击，收起即摘监听）；
- **必须配一条反向对照**：下拉收起时，同样的一击**必须到达画布**。
  没有它，"这个函数永远返回 `reachedCanvas=false`"也一样绿 —— 那又是空转。
- 自己踩到的坑（值得单独记）：`reachedCanvas` 必须在**派发给画布之前**判定。
  第一版写成派发之后再读 `stopped`，结果画布自己的 handler 也会调 `stopPropagation`
  （它在正常处理这一击），于是"真的到达了画布"被误报成"被拦下了"，
  反向对照断言红得莫名其妙。**"谁调的 stopPropagation"是有歧义的，别用事后状态推断因果。**

**如何防止复发**：写"某件事不应该发生"的断言时，必须同时写一条"它本来会发生"的对照。
这次的成品是三条：拦下（`reachedCanvas === false && !isDrafting()`）、
反向对照（`reachedCanvas === true && draftPoints === 1`）、
以及"对照用的顶点已被清掉"（否则它会污染后面的断言）。
鉴别力实测：临时去掉 `stopPropagation()`，两条断言同时变红并如实报出 `drafting=true` ——
**缺陷是真的，断言也是真的能红**。

### 5.29 守卫今天不可观测时，要把它写下来（"没红"也是一种结果）

**现象**：定义文件里有这么一道守卫 —— 只有"文件里真的出现过这一段"（`sections` 含该段）
才去合并那一段（`has('section')` 判断）。它是"导入绝不删东西"的技术保证之一：
一份 v1 老文件没有 `markers` 段，就不该动用户的标记定义。
但**在当前实现下它不可观测**：解析侧给缺失段的是**空数组**，而合并（`mergeById`）**只增不删**，
于是"合并一个空数组"与"跳过合并"的可见结果完全相同 —— 破坏这道守卫，
一条断言都不会红。这是 ⑤-1/③ 那一轮鉴别力验证时实测出来的（"没红"被如实报告，
而不是换个能红的断言来充数）。

**根因**：守卫防的是**将来**可能出现的语义变化（有人把合并改成"以文件为准覆盖"），
而不是当前代码路径上的缺陷。**当前不可观测 ≠ 没用**，但也**不等于**它现在在保护什么。

**修法（这一次是"不修"，而是记录）**：

- **不删**：一旦合并语义被改成"替换"，这道守卫就会立刻变成唯一的防线；
- **在注释里写明它今天不管事**（`resourceBundle.ts` 的段注释与本条），
  免得后来人读到 `has('section')` 就以为"缺失段已经被保护了"，
  从而在别处放松警惕（真正在保护的是"空数组 + 只增不删"这两条）；
- 真正钉死"导入不删东西"的断言留在数据层：v1 文件导入后
  "标记与路径类型一条都没少"（冒烟场景 36）+ 幂等（"刚导出的文件再导入 = 0 新增"）。

**口径**：**"破坏它也没有断言变红"是一个必须写下来的结果**。
它有两种可能 —— 守卫是冗余的，或者断言还没写到那个角落 —— 两种都值得记一笔，
但都不该用一条"凑数用的、能红的断言"盖过去（那就是 §5.24 的空转断言换了张脸）。

### 5.30 替身替掉了"清单被谁筛过"：选择器恒为空（用户实测）

**现象**：用户报"设置中的插件设置页内，导入新定义的 UI 工作不正常"。
实际情况是：点「导入定义文件…」之后，文件选择器里**一个候选都没有** ——
连刚刚用「导出定义文件…」导出的那一份也看不到，于是整条导入链路走不下去。

**根因**：`AssetSuggestModal` 是图片选择器与定义文件导入**共用的**那个弹窗，而它的 `getItems()` 写死了图片白名单：

```ts
override getItems(): string[] {
  return listImagePaths(this.options.files)   // ← 只认图片扩展名
}
```

`importResourceBundle()` 把 `listBundlePaths()` 的结果（全是 `.json`）交给它，被这一步**全部筛掉** → 空列表。
"共用一份实现"本身是对的（三条退化路径的文案只写一遍），错在**把"筛哪一类"也一起共用了**。

**为什么测试全绿**（这一条最值得记）：

- 冒烟里**所有**导入断言都走注入的替身（`setImagePickerFactory`）。替身能替掉"用户选了哪一项"，
  **替不掉"清单被谁筛过"** —— 而被测逻辑恰恰就在那一层；
- 真实弹窗的 `getItems()` **确实**被验过（"真实弹窗的清单：只含图片且顺序确定"），
  但**只有图片那一类**。也就是说：那条断言锁住了缺省行为，却没有任何东西检查
  **另一类要走另一条分支**。

**修法**：

1. 弹窗新增 `kind: 'image' | 'bundle'`，**由调用方给、并且是必填**；`getItems()` 按它选
   `listImagePaths` / `listBundlePaths`，占位文案也按类别给（`选择库内图片…` / `选择定义文件…`）。
2. `main.ts` 的两个调用点各自显式声明类别。`kind` 写成**必填而不是可选**：漏传会被编译期拒绝
   （`TS2345`）—— "忘记声明类别"这件事**写不出来**（同 §5.27 的思路）。
3. 新增 5 条断言（合计 **982**）：
   - 真实弹窗 `kind: 'bundle'` 列的是 `.json`、缺省提示是给定义文件用的（2 条）；
   - **整条导入链路改走真实选择器**：真弹窗里能看到刚导出的那份、候选**非空且全部是 `.json`**、
     选中之后仍然走到确认对话框（3 条）。

**鉴别力（实测，不是声明）**：

- 变异 1：把 `getItems()` 改回写死 `listImagePaths` → **3 条立刻变红**，
  失败信息如实报出 `["Assets/forest.png"]` 与 `[]`；恢复后 982 全绿。
- 变异 2：删掉调用点的 `kind: 'bundle'` → **根本跑不到冒烟**：`build.mjs` 自带类型检查直接失败（TS2345），
  产物因此没更新，紧接着**产物新鲜度门禁**拒绝用旧产物跑冒烟（两道门都按设计工作了）。
- 另有 2 条新增断言在上述变异下**不会**变红（占位提示、链路可走通）——
  它们锁的是另外两个性质，不是这条缺陷的守卫。如实记在这里（§5.29 的口径）。

**如何防止复发（这次的判据）**：看到一个"共用的 UI 组件 + 只按一种类别写死的筛选/白名单"，先问两句：

1. **另一类调用方传进来的东西，会被它筛掉吗？**
2. **有没有断言跑过"另一类"的完整链路**（而不是只跑替身、或只跑一类）？

替身的边界必须写清楚：**它替掉的那一层，就是永远不会被检查的那一层。**

- 复刻 vault 的 `process`/`create`/`modify` 事件与 mtime。

**加新功能时请同步加冒烟场景**：本项目的经验是"桩没模拟到的真实行为，就是下次用户报的 bug"。

  `fc-marker-image` 类"，而 `object-fit: contain` 写在 `styles.css` 里，
  **没有任何测试读过 `styles.css`，也没有任何真实渲染断言**（假 DOM 没有布局）。
  真实浏览器里"用户挑的图是否真的不被拉伸"必须人工看一眼。
- **带图片的标记拖动**：已经断言了前提（`img.draggable = false`），但"按住带图片的标记拖动
  是否跟手、指针链会不会断"在真实浏览器里未验证（这正是当初加 `draggable = false` 的原因）。
- **自定义标记的两处真实观感**：工具条图标组（内置 9 + 自定义，带显示名）在窄窗口下的换行与滚动；
  设置页图标预览在深色主题下的观感。
- **移动端 / 触控**对自定义标记同样完全未验证（与其它功能一样只按鼠标假设实现）。
- **路径与区域类型下拉（⑤-1 / ⑤-2）的真实观感**：浮层的定位与遮挡（下拉会不会被画布控件或
  窗口边缘切掉）、`z-index` 与主题差异、窄窗口下的换行与滚动、`max-height` 生效后的手感。
  `styles.css` 里那几行下拉样式**没有任何自动断言**（冒烟不读 CSS）。
- **真实浏览器里的事件传播只按契约验证过**：`firePointerThroughDocument()` 走的是
  "document 捕获阶段 → 画布容器"这两跳，**没有**让真实浏览器去传播一次。
  "点画布收起下拉时不会顺手落一个顶点"在实机上要人工确认一次（见 §5.28）。
- **定义文件的真实往返只在同一库内测过**：没有测过"跨库导入"（另一台机器/另一个库导出的文件
  导进本库）、几千条定义时确认对话框的观感与性能、以及 Obsidian 同步/移动端场景下的行为。
- **导出侧仍不体现区域类型的新参数**：SVG / PNG / Base 缩略图里区域用的是固定 0.28 不透明度、
  不画边框虚线（见下"已知的粗糙处"），所以"区域类型调好了导出却不一样"属于已知缺口。

### 已知的粗糙处（不是 bug，但有更好的做法）

- **标记图标不参与导出**：`src/base/mapPreview.ts` 对每个 `markers[]` 只画一个固定小圆点，
  所以 SVG / PNG 导出与 Base 缩略图里既没有自定义字形、也没有图片。
  内联图片（或把图标转成路径）属于后续工作。
- **区域类型的不透明度 / 边框只画在画布上**：导出 SVG 里区域仍是固定 `fill-opacity="0.28"`
  且不画边框虚线（`mapPreview.ts` 只读 `region.color`），所以导出图与画布在区域观感上会不一致。
  这是升级前就有的缺口，本轮没有扩大也没有修。
- **"自定义定义被删掉"没有运行时告警**：`resolveMarkerStyle` / `resolvePathType` /
  `resolveRegionType` 都会给出 `unknown: true`，但**绘制层不消费这个字段** ——
  `mapDocument.ts` 里"由绘制层告警"这句注释并不成立（源码里没有这条）。
  用户实际能看到的是界面上的**「未知（<ID>）」标签**（工具条下拉的当前项、图例条目），
  以及状态报告里对未知路径类型的标注（`main.ts` 的 `style.unknown ? '未知(ID)' : …`），
  再加上加载时那条"未知…已保留"的告警（只对非内置、非 `custom:` 的值发）。
  也就是说：**数据一定保得住，但"你删掉的那个定义还有对象在用"这件事只在界面上露出，不会主动提醒。**
- Base 视图一次性建表，**未做虚拟滚动**（几百行会卡）。
- 撤销栈上限 100，**不支持跨文件撤销**。
- 移动端完全没做：手势假设鼠标（双击、右键、中键）。

## 10. 附录 A：手动验证清单（给真实库用）

前面的状态标记：✅ = 已由用户验证通过；🔄 = 待验证。

### 10.1 数据层 ✅

1. 打开 `Maps/World.canvas` → `Ctrl/Cmd+P` → **创建地图并绑定到当前 Canvas** → 输入名字。
2. 应新建 `Maps/<名字>.map.md` 并在新标签页打开（frontmatter + 空 JSON 代码块）。
3. 运行 **查看当前 Canvas 绑定的地图** → 应报告网格、地形格数、文件体积、**名称字号与实测标定**。
4. 手工在 JSON 里加几格地形并保存 → 再运行状态命令 → 格数应随之变化。

### 10.2 渲染与绘制 ✅

1. 运行 **启用/停用当前 Canvas 的地图层** → 出现六边形地形与网格线，并报告本帧绘制统计。
2. **关键检查点**：网格必须与原生卡片处于**同一世界坐标系**（平移缩放时跟着卡片动、不漂移、
   放大不发糊）。
3. 按 `D` 进入绘制模式 → 左键拖动边拖边落笔；`1`–`9` 换地形、`[` `]` 调笔刷半径。
4. 一次拖动 = 一步历史（`Ctrl/Cmd+Z` 撤掉整条笔画）；`Esc` 回到选择模式。
5. 确认绘制模式下**中键平移**与**滚轮缩放**不受影响。

### 10.3 标记与文字 ✅

1. `D` → `M` 切标记工具 → 点一下地图 → 填名称/图标/可选笔记路径 → 应**吸附到格心**。
2. 选择模式下**点击**标记 → 打开对应笔记；**拖动**标记 → 跟手移动、松手吸附格心、可撤销。
3. **右键**标记/文字 → 删除（可撤销，空白处右键应弹原生菜单）。
4. `T` 放文字标注 → 缩放画布时字号应在可读区间内变化。

### 10.4 路径与区域（含命名）✅

1. `P` 切路径工具（工具条出现 河流/道路/贸易路线/边界）→ 逐点点击 → 回车或双击结束。
   河流应是**平滑曲线且末端渐细**，预览与结果形状一致。
2. `R` 切区域工具 → 至少 3 点 → 双击结束 → 半透明多边形。
3. 结束后**立刻弹出命名框**；点「跳过」→ 形状**仍然存在**，只是没名字。
4. 命名为「北境商路」→ 名称应**贴着线条走**（字的倾角随线条方向变化）；
   凹区域（如 "∩"）的名称必须落在**形状内部**。
5. `Ctrl+Z` 只撤销命名（形状还在），再按一次才撤销形状。
6. 选择模式下**双击**河流/区域 → 改名框且预填当前名；清空后确定 → 名称消失（可撤销）。
7. 工具条最右的「名称」按钮 → 一键隐藏/显示所有名称。
8. 设置里拖动「路径与区域名称的字号」→ **字形本身**应立刻变化（不只是描边）。
9. 命名框打开时在输入框里打 `p` / `r` / `b` **不应**切换工具。

### 10.5 Base 视图 🔄（待验证）

1. 命令面板运行 **创建地图 Base 文件（表格视图）** → 得到 `Maps/World.base`。
2. 打开它 → 把视图类型切换为 **地图**（视图选择器里应出现）。
3. 表格应列出地图上的标记/区域/路径 + 库里带 `coordinates` 的笔记：
   **来源**列区分「笔记」/「地图」，**坐标**列显示世界坐标，点名称跳转对应文件。
4. 表格上方应出现地图缩略图，包含地形色块、路径、区域、地图标记和笔记坐标点。
5. 分别点击缩略图中的地图标记、路径、区域、文字标注和笔记点：应打开对应的地图文档或笔记。
6. 调整 Base 容器为宽而矮、窄而高两种形状：地图应保持等比例，允许出现留白，但不应被拉伸。
7. 给某篇笔记加 `coordinates: [320, -140]` 与 `map-type: city` → 表格与缩略图出现该行/标记。
8. 故意写错（`coordinates: 东边那座城`）→ 该行标红，表格下方列出这篇笔记的路径。
9. 视图选项面板里改「地图文档」/「排序」→ 表格应跟着变。
10. 未配置地图文档时：库里只有一张地图应自动选用；多张时应只显示笔记侧并给出配置提示。
