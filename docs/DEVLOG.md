### 2. 编辑与检查器（A1 / A2 / A3）

| 轮次 | 交付 |

| **A2 侧栏就地编辑** | 类型（图标/地形/路径类型/区域类型）、位置（x/y、"移到视口中心"）、外观（覆盖色/颜色/线宽/虚线/不透明度/边框）；三组**默认收起** |

### 2aa. 地标在缩放时位置漂移：投影改成「闭式 + 权威采样裁决」（用户实机报的缺陷）

用户原话：「地标在放大缩小视图的时候会不准确的移动。」

**根因（代码核查 + Phase 0 实测对照）**：标记 / 文字是挂在**未变换** wrapper 上的 DOM billboard，
每帧由投影算屏幕坐标；而投影的原点用的是**闭式关系** `origin = wrapperRect.topLeft + matrix(e,f)` ——
它来自 Phase 0 **一次实测**（1.13.7，scale≈0.447，吻合 0.03 px）。闭式是精确值、无量化噪声，
但**换版本 / 换布局时它可能带上一个与缩放有关的偏移**；而投影唯一可见的消费者恰恰就是那层 DOM billboard，
于是症状正好是「放大缩小时地标移动不准」。

**修法**：`src/core/projection.ts` 新增纯函数 `resolveProjection()`，`buildProjection()` 每帧用它裁决：
- 采**两个彼此远离**的 `posFromEvt` 点（视口 20% / 80%），得到权威的 origin 与 scale；
- **一致（差 ≤ 噪声上界 1.5 倍）⇒ 继续用闭式**（不把 posFromEvt 的 1px 量化引进每帧）；
- **不一致 ⇒ 信采样**（缩放差 >1% 用采样缩放、原点差 >1.06px 用采样原点），并写一条 note；
- 采样结果按「画布 + 矩阵(a,e,f) + 视口矩形」指纹缓存，避免每帧重复采样。

**冒烟回归**：标记场景新增一条 —— 标记的屏幕位置必须等于 `posFromEvt` 映射出来的位置（Δ ≤ 1.5px）。
它直接盯住这类漂移：投影与权威源不一致就会红。冒烟 1565 → **1566**。

**验证强度**：单测 689 → **694**（新增 5 条：一致用闭式 / 闭式偏了信采样 / 缩放不一致两边都用采样 / 只有一侧证据 / 噪声不触发切换）；
构建 91 模块 / 1577.5 → **1584.5 KiB**。

**踩到的坑（自测抓到的）**：第一版缓存指纹只含「缩放 + 视口矩形」，**不含矩阵平移** ⇒ 平移时闭式原点变了、
缓存却不失效，位置被冻住（冒烟两条「平移改变位置」当场红）。指纹必须含**全部输入**。

**没做 / 未验证（如实列出）**：① **真机确认只能你试**（缩放几次看地标是否跟着走）；② 若你的 Obsidian 上
闭式与采样**一致**，这次修复不改变任何行为（也不会打 note）—— 那就说明漂移另有原因，请把控制台里
`[project-kaki]` 的提示发我；③ 触摸 / 触控笔缩放仍未验证。

### 2ab. 缩放时地标「跟着走但不准」：采样跨动画两帧 → 加稳定性闸；顺带三个按钮改名（用户实机）

用户实机反馈：「缩放时跟地图走，但是不准。在一次平移后复原。」——**这条描述直接指出了根因**：
位置在平移后复原，说明错的不是闭式，而是**那一帧的裁决结果**。

**根因**：Obsidian 的缩放是**动画**。1.2.1 的裁决要采两个 `posFromEvt` 点，而这两次调用**可能跨在动画的两帧**上
—— 两个时刻拼出来的缩放是假值；`resolveProjection` 又因为它与矩阵相差 >1% 而**优先采用它**，那一帧的投影就带上了错的缩放。
缩放停下后矩阵不再变、缓存命中，错误一直留着，直到**下一次平移**改了指纹才重算 —— 与用户观察完全一致。

**修法（三道闸）**：① **采样前后各取一次变换指纹**（宿主元素 CSS transform + 视口矩形），不一致就**整帧不采信、且不写缓存**
（保持原来的精确路径，下一帧稳定后重新裁决）；② **采样对与矩阵缩放差 3 倍以上**整组不作数；③ 原有的噪声上界判据保留。

**顺带改名**（用户：「沿格心」明明是锚点绘制；另外两个名字也很奇葩）：沿网格线连接 → **沿网格走** · 格步进 → **逐格前进** ·
沿格心连接 → **锚点折线**（`mode` 取值与老数据都不变）。改名只动 `src/ui/strings.ts` 的常量 —— C4 的回报：
**冒烟 1601 条一条都没红**（断言读常量，不读字面量）。

**验证强度**：单测 695 → **696**；冒烟 **1601 → 1601**；构建 91 模块 / 1587.0 → **1589.1 KiB**。

**没做 / 未验证（如实列出）**：① 动画期间采样的那两道闸**没有自动化测试**（假画布不会自己动起来），靠用户实机复测 + 推理；
② 三个按钮的新名字是否合口味要看用户；③ 触控笔缩放仍未验证。

## 三、这个周期确立的关键决定（改主意前先读这里）

1. **未知值一律保留**：不认识的 ID / 字段 / 段落 / 格上键，一律原样保留 + 告警，回退视觉归绘制层。
2. **一个设置只有一个来源**：旧设置字段迁移后只当镜像（`pathColors` / `regionColors` / `layerVisibility` 的 legacy）。
3. **样式只影响新对象**：已画对象的参数存在地图文件里；改设置不动它们。
4. **显式模式，不做隐式推断**：字形/图片、单格/整片、逐格/连续场都是显式字段。
5. **表驱动**：选中种类、图层、字段规格、筛选规则各有一张登记表，"加一种"= 加一行。
6. **画布与导出共用几何**：连续场的图元 IR 只有一份（`fieldPlan` → `overlayPlan` → 画布 / SVG）。
7. **可撤销**：任何写文档的编辑都走既有 history 路径，一次操作 = 一条历史。
8. **覆盖层永久 `pointer-events: none`**；手势只在容器捕获阶段处理，UI 排除按元素引用。
9. **定义随图（方案 B，用户 m01845 裁定）**：一张地图自带它用到的**全部定义**（地图文件顶层 `definitions`）；
   库级那一份降级为**「新建地图的模板」+ 老图（v1）的迁移快照**，写入时**两处一起更新（镜像）**；
   v1 老图**一个字节都不动**（读时拿库级设置做内存快照，只有真改了定义才回写升版）。
10. **「按地图分份」的键 = 库内相对路径，缺则回落模板**：`settings.mapViews[地图路径].{overlays,layers,showLegend}`
    三个字段**各自可选、按字段回落** ⇒ **老配置迁移不需要写一行代码**，也不给现有地图各复制一条记录。
11. **画布上的东西按"它自己那张图"解析**：覆盖层 / 工具条 / 图例用 `mapPathForCanvas(canvasPath)`，
    只有侧栏 / 设置页 / 报告跟活动画布（`activeViewMapPath()`）—— 两者**刻意不是同一个入口**。
12. **视图偏好不进地图文件**：判据是"这是**怎么看**，不是这个世界的事实" —— 分享一张图不该把对方的
    配色 / 图层 / 图例一起改掉（定义进文件、偏好不进文件，这条分界要一直守住）。
13. **定义文件是"搬运工具"**：导出**当前地图**的定义集（路径 / 区域类型**含内置项的参数**），
    导入**只增不删**、同名冲突逐条让用户勾「覆盖」；且**先说后做** —— 对话框上写的目标就是落盘的目标。

## 六、ISSUE-005 · 绘制模式拆出「自由绘制」（2026-09-30，用户实测）

> 记录与四条验收在 `docs/ISSUES.md` ISSUE-005；教训见 `ENGINEERING-NOTES.md` §5.80。

**用户原话**（m01983）：「3.沿格心连接/自由绘制（这里有历史遗留问题：穿内部应该分成格子中心连线和
完全没有锚点的绘制。）」

**根因**：`GeometryMode` 只有 `interior` / `edge` / `edge-step` 三个取值，而 `interior`（原名「穿内部」）
同时接住了"点几个点连成过格心的折线（有锚点）"与"完全没有锚点地随手画"两种操作 ——
判别依据只存在于用户当时的操作路径里，**没有写进数据**。

**改了什么**：

| 层 | 改动 |
|---|---|
| 数据 | `GeometryMode` 新增 `free`；`readGeometryMode` 认得它，**其余仍回退 `interior`**；老数据不迁移、不改写 |
| 编辑器 | `MapDraft` 记 `mode`；`free` 不吸附、不做沿边走、提交原样、**不叠平滑**；新增 `extendFreeDraft()` 收轨迹点 |
| 交互 | `MapInteraction` 新增自由绘制手势：`pointerdown` 开始（`setPointerCapture`）、`pointermove` 按**屏幕 4px** 最小间距收点、`pointerup` 一次性提交（`pointercancel` / 丢焦点则丢弃） |
| 渲染 | `drawDraft` 按 `draft.mode !== 'free'` 决定画不画顶点手柄 |
| 界面 | 侧栏 `GEOMETRY_OPTIONS` 三项 → 四项；模式名与 ≤20 字 hint 的**单一来源**是 `src/ui/strings.ts`；浮窗文案改读同一份 |

**验证强度**：单测 694 → **695**（`tests/mapDocument.test.ts` +1：free 往返、缺 mode / 坏值回退 `interior`、
解析→序列化稳定）；冒烟 **场景 21 扩写 +17**（1566 → **1583**）：按钮 3 → 4、顺序与 hint 与常量逐字相同、
自由绘制端到端（不吸附 / 最小间距 / 抬手提交 `mode === 'free'` / 保留每个采样点 / 不平滑 / 一次绘制 = 一条历史 /
草稿清空）、**渲染层判据**（草稿确实在画 `stroke ≥ 1` 而 `arc === 0`）、`free` 落盘往返与"`interior` 没被迁移"。
构建 91 模块 / 1584.5 → **1592.9 KiB**。

**破坏性验证（2 处，逐处确认变红后还原）**：
① `drawDraft` 取消 `free` 的手柄豁免 ⇒ 冒烟 1 条红：`自由绘制的草稿不画可拖顶点手柄 — arc=6`；

## 九、新增第五个绘制模式「沿格心走」（2026-09-30，用户要求）

> 记录与验收在 `docs/ISSUES.md` ISSUE-006。

**用户原话**：「那加一个沿着格子中心走的绘制模式。」

**为什么缺**：四个模式里没有一个"把落点吸到格心、依次穿过去"——`edge` 吸的是格顶点、`edge-step` 走格边、

但它只是"折线恰好路过格心"，落点并不吸附，于是"穿过哪几个格子一目了然"这件事没有工具能做。

**改了什么**：

| 层 | 改动 |
|---|---|
| 几何 | `src/core/hexEdges.ts`：`GeometryMode` 新增 `center`；新增纯函数 `snapPointToCellCenter(grid, point)` /
  `isSameCell(grid, a, b)` / `snapPointsToCellCenters(grid, points)`（吸附 + 丢连续同格）。 |
| 编辑器 | `src/editor/MapEditor.ts`：`snapDraftPoint` 对 `center` 吸格心；`addDraftPoint` 对"落到同一格"的点击不再加点；
  `draftDisplayPoints` 让预览的橡皮筋端点也吸附；`commitGeometry` 原样提交（不再走沿网格线的 `toEdgePath`）；
  `smooth` 只在 `interior` 置位（`center` 自然不平滑，理由写进注释）。 |
| 数据 | `src/data/mapDocument.ts`：`readGeometryMode` 多认一个 `center`，其余仍回退 `interior`（老数据零改动）。 |

| 渲染 | **一处未改**：`drawDraft` 的判据本来就是 `draft.mode !== 'free'` 才画顶点手柄 ——

**破坏性验证（2 处，逐处确认变红后还原）**：
① `snapDraftPoint` 对 `center` 不吸附（退回点击的像素位置）⇒ 冒烟 **3 条红**：
  `沿格心走的起点吸附到格心（不是点击的像素位置）`、`每一个锚点都精确落在格心（≤1e-6）`、`两个顶点都精确落在格心（≤1e-6）`；
  （去重那条**没红**：它用 `addDraftPoint` 送两个落在同一格的不同像素，`isSameCell` 按格身份判断，不依赖吸附）；
② `readGeometryMode` 不认 `center` ⇒ 冒烟 **2 条红**：`重新解析后 center 仍是 center（没有被回退成 interior）`

**没做 / 未验证**：

- **手感没在真实 Obsidian 里看过**："点一格吸一格"的落点反馈、密集点击时的观感、以及长路线（几十格）时的顶点数是否可接受，

## 十三、ISSUE-007：离开 Canvas 之后面板必须整块空掉（2026-10-06，用户报"致命"）

**用户原话**：「有一个致命问题。今天才发现。这个侧边栏离开原本的 canvas 文件过后还可以接着在
其他的文件里面用。而且状态是保存的。」

**根因（两处"退路"都只问"哪张画布开着"、从不问"用户在看什么"）**：

1. `CanvasAdapter.activeCanvasHandle()` 的 `handles.find(h => h.isActive) ?? handles[0]` ——
   活动叶子变成一篇普通笔记时，没有任何 canvas 的 `isActive` 为真，于是**退回列表里的第一张后台画布**，
   "当前地图"仍然是它（**这是本缺陷的主入口**）；
2. `MapLayerManager.getInspectorEditor()` 自带三级回落（活动画布 → 有选中项的画布 → 最近交互过的），
   而侧栏面板的"当前编辑器"正是取它（`main.ts` 的 `toolControlsHost()`）⇒ 只修第 1 处**照样能拿到那张
   后台画布**。

**为什么当初会写成这样（不是笔误，是把两件事混了）**：退路是为"**点侧栏 / 点面板自己**"写的 ——
那时活动叶子是个**没有文档**的视图（面板），若直接返回 `null`，面板自己的控件按一下就会丢当前地图。
正确的结论表是**三档**：某张 Canvas → 就是它；**别的文档（笔记 / PDF…）→ 没有当前地图**（当初漏了）；
插件面板 / 没有文档的视图 → 沿用"最近那张画布"。

**落地清单**：

| 处 | 改动 |
|---|---|
| `canvas/CanvasAdapter.ts` | 新增 `activeViewIsOtherDocument(app)`（**有 `file`** 且 `getViewType() !== 'canvas'`）；"活动视图"的解析抽成 `resolveActiveView()` 供两处共用（`findCanvasHandles` 的 `isActive` 判定也改读它，避免"谁是活动的"出现两种答案） |
| 同上 · `activeCanvasHandle()` | 退路加闸：`... ?? (activeViewIsOtherDocument(app) ? null : handles[0] ?? null)` —— 退路的原用途（点侧栏 / 点面板）一字不动 |
| `render/MapLayerManager.ts` | `getInspectorEditor()` 开头加**同一道闸**（`activeCanvasHandle()` 为 `null` ⇒ 直接 `null`），三级回落只在"确实在画布上"时生效 |
| `ui/strings.ts` | 新增 `PANEL_EMPTY_HINTS`（两句：`noActiveMap` / `noLayer`）—— 空态文案分家，且被冒烟逐字钉住 ⇒ 满足 C4 判据 ① |
| `ui/toolSections.ts` | `ToolControlsHost` 多一个必填 `hasActiveCanvas()`；三节空态按它二选一 |
| `ui/MapPanel.ts` | `MapPanelDeps` 多一个必填 `hasActiveCanvas()`；「视图」一节的图层 / 图例 / 「画法」开关在无当前画布时**整块置灰**（保留控件、不删，§F.2 那条口径），「画法」正文不渲染 |
| `main.ts` | 新增 `hasActiveCanvas()`（`activeCanvasHandle() !== null`）并接线到面板与三节；`describePanelSummary()` 分清"一张画布都没开"与"画布开在后台、用户在笔记里"（后者不再谎称"没有打开 Canvas"，也不再谎称"地图层已启用"） |

**四道门**：构建 **91 模块 / 1616.7 KiB** · `tsc` **0 错** · 单测 **706**（`tests/canvasFocus.test.ts` +6）·
冒烟 **53 场景 / 1645 断言**（场景 53 +18）。

**破坏性验证（四处，每处确认变红后还原）**：

| 变异 | 变红的断言 |
|---|---|
| 摘掉 `activeCanvasHandle()` 的闸 | **11 条**（检查器不为空、三节仍是旧状态、开关仍可点、状态行仍说"已启用"…） |
| 摘掉 `getInspectorEditor()` 开头的闸 | **4 条**（检查器不为空、工具一项仍有 9 个地形按钮、选择方式仍有 2 个按钮、三节文案） |
| 空态文案不分家（`noActiveMap` 换回 `noLayer`） | **2 条**（"三节都改成…"、"一处都不再说没有启用的地图层"） |
| `describePanelSummary()` 退回旧顺序（先看有没有启用的地图层） | **1 条**（"顶部状态行不再说地图层已启用"） |

**如实记（未做 / 边界）**：

- **"点一下置灰的图层开关不该有写入"这条断言没写**：真浏览器不派发 disabled 按钮的 click，但**假 DOM 会** ——
  在桩里写它等于测"处理器有没有跑"，永远绿，是假断言（`ENGINEERING-NOTES.md` §5.84 第 4 条）；
- **多画布那条细化没做**（顶部状态行的"已启用"仍按"库里有没有启用的地图层"判断，而不是"活动那张画布有没有启用"）：
  它在"两张画布同开、活动那张没启用"时仍会说谎，但那**不在本次缺陷范围内**，且桩里只有一张 canvas 叶子、
  加断言要先搭第二张画布 —— 如实留给下一轮（`ENGINEERING-NOTES.md` §7 已列）；
- **ISSUE-007 §3 的第 ③ 条（两张画布同开，点侧栏不丢选中）在桩里证不出来**，必须实机验；
- **实机观感未看**：下面 6 条要在真实 Obsidian 里过一遍（本轮只跑 `deploy.mjs` 到 test-vault，
  **没有**动真实库、没有 commit / push）。

**可判伪的实机验收步骤**（与 `ISSUES.md` ISSUE-007 §3 同源）：

1. 打开 Canvas + 启用地图层，随便玩一会儿（选几格 / 切工具）→ 切到一篇普通笔记：
   面板「工具 / 笔刷 / 选择方式 / 视图」四节都显示**「当前没有打开的地图：切回一张 Canvas…」**，
   **不再**残留上一张图的工具按钮 / 地形调色板 / 选择读数；
2. 同场景点面板里任何按钮（工具 / 动作 / 图层开关）：**点不动**（灰），控制台无写入、地图文件零字节变化；
3. 打开**两张** canvas（都绑定地图）：在 A 上选中几个格 → 点侧栏输入框 → 面板仍显示 A 的选中
   （多画布那条口径不许被这次改动弄坏）；
4. 切回 Canvas：面板**立刻**恢复成那张图的状态（不需要重开面板）；
5. 一张 canvas 都没开：行为与今天一致（命令给"请先打开 canvas"、面板顶部写「当前没有打开 Canvas」）；
6. 在**非 canvas 文件**下点侧栏图标：面板仍能打开（内容为空态），不是打不开。

**教训**：`ENGINEERING-NOTES.md` §5.84（"`?? handles[0]` 这类消歧退路必须把'用户在看别的文档'单列一档"，
含"闸要加两处""置灰 ≠ 写不进去""桩缺一个全局对象会让整条分支看起来没实现"）。
