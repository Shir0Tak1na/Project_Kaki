## 2. 长文案：三条硬规则 + 逐条改法

### 规则（建议写成实现纪律）

1. **控件旁可见的说明 ≤ 20 字**，只回答"这是什么 / 留空会怎样"；
2. **超过 20 字的，拆成「短标题 + 可展开说明」**（`<details>` 或「?」工具提示），默认收起；
3. **技术细节不进界面**：字段名（`path.cap`）、文件格式（`{"version":2,…}`）、ID 正则这类，属于手册与
   错误报告，不属于设置页。

## 4. 排版：一大坨怎么拆

**面板（`MapPanel`）**：按"一眼能扫完"分块，每块**首行是一行摘要**，细节默认收起：

```
当前状态        编辑：地形笔刷 · 森林          ← 一行，最重要
工具            地形 / 路径 / 区域 / 标记 / 名称 + 笔刷大小   ← 常用
显示            底图 · 地物 · 数值图层          ← 三个折叠组
选择            方式 · 筛选 · 整批编辑          ← 折叠
地图定义        管理地图定义…                  ← 一个按钮
```

**规则**：① 一个块内**一行一个控件**，不要一行塞三个；② 说明文字统一**放在控件的下方或工具提示**，
不要插在控件之间；③ 数字输入**并排 + 单位后缀**（`10` `℃`），不要写进标签；④ 组与组之间留一行空白；
⑤ 次要组**默认收起**（已有的 `<details>` 用法照旧）；⑥ 一行内标签左对齐、控件右对齐（Obsidian `Setting` 已是）。

**设置页**：同上，且**只留"新对象默认值"**（§A3 已做），把仍显臃肿的说明按 §2 规则砍。

**禁止**：在这些文件上与他并行改文案 —— 同一工作区、同一份文件的两处并发写，**谁最后写盘谁赢**
