# 可借鉴的改进（成熟编辑器挖掘 · 待办池）

> **这份文件是什么**：从几套成熟编辑器里挖出来、**值得这个插件借鉴**的东西，每条都写明
> 「来源 / 我们现状 / 怎么落 / 成本 / 依赖 / 可判伪验收」。
> 它不是排期——排期在 `DATA-LAYER-PLAN-v5.md` §G；这里只是**候选池**，用户/工头按需取用。
>
> **来源**：Minecraft（数据格式与标签）、**WorldEdit**（区域编辑）、**Tiled**（瓦片与变体）、
> **Blender**（操作后调参）、**QGIS**（图层样式与表达式）、**Aseprite**（选择工具）。
> **核实过的事实**写在"我们现状"里（带文件位置），不是印象。

## 0. 先说三条"已经买好但没用"的地基（性价比最高）

### 0.1 `TerrainCell.f` 位标志：**解析与序列化都在，渲染一个都没消费**

- **来源**：Tiled 的 Wang tile / 变体索引；Minecraft 的 block state（`facing` / `half` / `shape`）。
- **我们现状**：`mapDocument.ts:458` 解析 `f`（1=旋转、2=镜像、4=变体）、`mapDocument.ts:902` 写回，
  **但全仓没有任何渲染代码读它**（grep `variant|rotate|mirror` 只命中标签/标记/矩阵）。
- **怎么落**：地形绘制时按 `f` 选择"变体图 + 旋转 + 镜像"；再进一步做**按邻居自动选变体**
  （Tiled 的 autotile：按上/右上/…/六邻域决定用哪张图）。
- **成本**：中（需要变体图源；几何与图集要扩展）。**依赖**：自定义地形/图集的变体资源。
- **验收**：给某格手写 `"f": 1` → 画布上的地形**真的旋转 60°**（断言读 ctx 的变换或图集索引）。

### 0.2 生物群系的**标签**已经落地（`docs/BIOMES.md` §3 + `src/render/biomeCatalog.ts` 的 `BIOME_TAGS`），但**地形还没有标签**

- **来源**：Minecraft block tags（`#minecraft:logs`、`#minecraft:water`）。
- **我们现状**：9 种内置地形只有 `TERRAIN_TYPES` 名单，没有分组；
  筛选器无法表达"所有水域"、笔刷无法"只刷水域"、图例无法按组折叠。
  **生物群系那一侧已经做完了**（23 个标签、`biomeTag` 筛选规则、一对多），所以这条路已经有现成参照物。
- **怎么落**：`TERRAIN_TAGS` 一张登记表（与 biome 标签**同一套 IR** —— 现在这套 IR 真的存在于代码里了）+ 筛选器加 `terrainTag` 规则。
- **成本**：小（一条表 + 一条规则）。**依赖**：无（可以立刻做，按 `biomeCatalog` 的标签表照抄形状）。
- **验收**：筛选 `terrainTag in [water]` → 选中的格恰好是水域/沼泽/（含自定义水域地形按标签）。

### 0.3 版本迁移目前是"散落的条件判断"，没有**迁移链**

- **来源**：Minecraft 的 DataFixerUpper（逐版本 fix，而不是到处 `if`）。
- **我们现状**：`MAP_DOCUMENT_VERSION` + 解析入口里的兼容处理；每加一个字段就多一处分支。
- **怎么落**：把 `parseMapDocument` 的兼容逻辑重构成**纯函数迁移链**
  `[v1→v2, v2→v3, …]`，每条带单测；解析时按版本顺序套用，未知更高版本仍只读打开。
- **成本**：中（重构解析入口，但行为必须逐字节不变）。**依赖**：~~最好在加 `dataDefaults`/`biome` 前做~~
  ⚠️ **那个"最省事的窗口"已经过去了**（`dataDefaults` 与 `biome` 都已进文件格式）。
  现在做仍然值得，只是迁移链一上来就要覆盖这两个新段落 —— 正好也证明它管用。
- **验收**：一串"旧格式样本 → 迁移后 == 现行格式"的断言（每条迁移一条），
  且现有全部单测/冒烟不变。

## 1. 编辑能力（WorldEdit / Aseprite 一脉）——**收益最大的一类**

### 1.1 选区**复制 / 粘贴（图章）**，并可**旋转 60° / 镜像** ⭐ 最推荐

- **来源**：WorldEdit 的 `//copy` `//paste` `//schematic`；六角旋转比它的 90° 更自由。
- **我们现状**：**完全没有**（grep `clipboard|paste|stamp` 无命中）。
  实际痛点很具体：画一条山脉、一片森林、一座城镇时，只能一处一处刷。
- **怎么落**：
  1. `src/render/clipboardStamp.ts`（纯函数）：`选取 → { cells: [{dq, dr, terrain, f, biome, temp, depth, c}] }`，
     以及 `粘贴(片段, 锚点, 旋转 steps, 镜像) → 格映射`（六角轴向坐标的 60° 旋转是整数变换）；
  2. history：**一次粘贴 = 一条历史**（复用现有 op 机制，别绕过撤销栈）；
  3. 选择工具上加两个动作：「复制」「粘贴到此处」；右键/快捷键可选；
  4. 第二步再做**导出成文件**（`.kaki-stamp.json`，与定义文件同一套导入导出纪律）。
- **成本**：中。**依赖**：§C 选择系统（需要"当前选择"这个输入）。
- **验收**：复制 3 格（含温度/biome/覆盖色）→ 粘贴到别处 → 三格的值逐项一致；
  旋转 60° 后形状仍闭合（面积不变）；`Ctrl+Z` 一次撤销整次粘贴。

### 1.2 选区的**扩展 / 收缩 / 边界 / 方向推**（WorldEdit `//expand //contract //outline //walls`）

- **我们现状**：只有"按同地形连通扩展"。
- **怎么落**：四个纯函数动作（六邻域），走 §C.2 的"动作"通道。
- **成本**：小。**依赖**：§C。**验收**：扩展 1 环后格数增加等于边界格数（可数）。

### 1.3 `//replace A B`：选区内的**替换**语义（而不是一律"设为"）

- **我们现状**：§C.5 的整批编辑是"设为某个值"。
- **怎么落**：批量编辑加一个"仅替换自 X"选项（对地形与数值都适用）。
- **成本**：小。**验收**：选区内混合地形 → 只把森林换成针叶林，其余不动。

### 1.4 **"调整上一步"浮层**（Blender 的 Adjust Last Operation）

- **来源**：Blender 操作后左下角的"调整上一步"面板；Aseprite 的笔刷参数回显。
- **我们现状**：刚做的操作参数（笔刷半径/数值、粘贴的旋转）**改不了**，只能撤销重做。
- **怎么落**：把"最近一次操作 + 它的参数"放进左上角状态浮窗（§F.3 已经要搬过去），
  改动参数 = **一条新的历史**（或在同一条历史内替换，二选一但要写清）。
- **成本**：小-中。**依赖**：§F.3 浮窗改造。
- **验收**：刷完一笔 → 在浮层把半径从 2 改成 4 → 结果按新参数重算且只多一条历史。

### 1.5 **撤销历史面板**（Photoshop / Aseprite）

- **我们现状**：撤销栈上限 100，只能一步步退。
- **怎么落**：列出最近 N 步（用 op 的 `label`），点哪步退到哪步。
- **成本**：中（要么快照、要么重放）。**验收**：从第 12 步直接跳回第 3 步，再 `Ctrl+Z` 行为一致。

## 2. 选择与筛选

### 2.1 **按值容差的"魔棒"**（Aseprite / QGIS）

- **现状**：规则已有 `temp between`；但"取这一格的值 ± 容差"要手打两个数。
- **怎么落**：选择工具加"魔棒"：点一格 → 用该格值 ± 默认容差（容差可调）构造规则。
- **成本**：小。**验收**：点一格 12 ℃、容差 3 → 选中 9–15 ℃ 的所有格。

### 2.2 选择形状**扩展**（WorldEdit `//sel poly / convex / cyl`）

- **现状**：§C.3 列了单选/矩形/笔迹。
- **怎么落**：加"多边形（点若干顶点闭合）"与"圆盘（六角距离半径）"。
- **成本**：中。**验收**：多边形选中集合与"点在多边形内"的纯函数断言一致。

### 2.3 **把选中内容导出成表格/笔记**（QGIS 属性表）

- **来源**：QGIS 的属性表；本插件已有 Base 行与报告面板。
- **怎么落**：选择 → 生成 Markdown 表格（坐标/地形/温度/深度/biome）→ 写进笔记或报告面板。
- **成本**：小（纯函数 + 已有报告面板）。**验收**：3 格选择导出 3 行，字段与文件一致。

## 3. 渲染与视觉

### 3.1 **图层混合模式**（QGIS / Photoshop）⭐ 便宜且观感提升明显

- **现状**：全仓没有 `globalCompositeOperation`（无混合模式）。温度/深度叠在山地上是直接盖上去的。
- **怎么落**：图层样式加一个"混合模式"下拉（`source-over` / `multiply` / `screen` / `overlay` /
  `soft-light`），绘制该层时设置、画完还原（沿用现有的"状态用完必须还原"习惯）。
- **成本**：小。**验收**：切成 `multiply` 后，同一张图的山影能透出来（断言读取 ctx 的
  `globalCompositeOperation` 在绘制期间被设置、之后被还原）。

### 3.2 **每层的总不透明度**（QGIS）

- **现状**：只有数据层有 `opacity`；地形/路径/标记层没有。
- **成本**：小。**验收**：把路径层降到 50% → 描边 alpha 变化且不影响其它层。

### 3.3 **色觉友好色带预设**（QGIS / matplotlib）

- **现状**：色带是用户自定义锚点，没有内置预设。
- **怎么落**：预设里加 `viridis` / `cividis` / `RdBu`（反色）等几条，一键套用。
- **成本**：极小。**验收**：套用后锚点值可复现（纯函数断言）。

## 4. 工程与数据

### 4.1 **"派生数据不入地图文件"成文**（Minecraft：level.dat vs 缓存）

- **现状**：连续场栅格、图集、缩略图都在内存/缓存；但**没有一条成文纪律**禁止把它们写进 `.map.md`。
- **怎么落**：写进 `EXTENSION-POINTS.md` 的硬约束清单，并加一条冒烟断言：
  序列化后的文本里**不含** `raster` / `atlas` / `cache` 这类键。
- **成本**：0（文档）+ 1 条断言。**验收**：故意往文档塞一个 `fieldRaster` → 断言变红。

### 4.2 **自定义与内置同名时的优先级**（资源包模型）

- **现状**：定义文件导入时"同 ID 保留现有"（`mergeById`）；但"自定义能否覆盖内置"没有成文。
- **怎么落**：明确"内置不可被覆盖（ID 撞不上，因为自定义带 `custom:`）"，
  并把 `custom:` 命名空间写成**不可变的约定**（生物群系同理）。
- **成本**：0（文档）。**验收**：尝试用自定义 biome 取内置 ID → 被拒并给出可读原因。

## 5. 交互与可发现性

### 5.1 **调试浮层**（Minecraft 的 F3）

- **现状**：`stats` 里有帧图元数、缓存命中、选中数等，但**只有命令/报告能看到**。
- **怎么落**：一个可切换的调试浮层（默认关），显示帧时间、图元数、缓存命中、选中格数、文档体积。
- **成本**：小。**验收**：打开后数值随操作变化；关闭后 DOM 里不残留浮层节点。

### 5.2 **把"选择方式 / 笔刷模式"也做成命令**（可绑快捷键）

- **现状**：这些只能点 UI；快捷键只覆盖一小部分（绘制/撤销等）。
- **成本**：小。**验收**：命令面板里能搜到并执行，且与点 UI 效果一致（同一条实现）。

### 5.3 **统一的状态/结果提示条**

- **现状**：Notice（≤6000ms）与报告面板两条路，位置不固定；§F.3 已计划把状态条放左上角浮窗。
- **怎么落**：所有"最近一次操作结果"统一走那条状态条；长文本仍走报告面板（§5.16 的口径不变）。
- **成本**：小。**验收**：连续做 3 次操作，状态条显示最后一次；不弹 3 个 Notice。

## 6. 我建议的取用顺序（按"收益/成本"排）

| 顺序 | 项 | 为什么排这里 |
|---|---|---|
| 1 | **§0.2 地形标签** | 极小成本、立刻让筛选器好用，且**与生物群系标签共用同一套实现**（一起做最省） |
| 2 | **§3.1 图层混合模式** | 极小成本、观感立刻提升；风险低（一处赋值 + 还原） |

| 4 | **§1.1 复制/粘贴（含 60° 旋转）** | 编辑收益最大，但依赖 §C 选择系统；排在 C 之后 |

| 6 | **§1.4 调整上一步 / §5.1 调试浮层 / §5.2 命令化** | 交互与排障体验，等 §F.3 浮窗改造时一起做 |

## 7. 与既有决定的关系（避免打架）

- §1.1 / §1.2 / §1.3 / §2.x **全部走 §C.2 的"动作"通道**，不新增"规则"；
- §3.1 混合模式是**图层样式**，与"分类配色表 / 渐变色带"并列，不替代；
- §0.2 地形标签与 `docs/BIOMES.md` 的标签**共用同一套 IR 与 UI**，别写两份；
- §4.1 与既有"未知字段一律保留"不冲突：**保留**是指用户数据，**缓存**是我们自己的派生数据；
- 所有项都遵守：覆盖层 `pointer-events: none`、一次操作一条历史、四道门、断言必须有鉴别力。
