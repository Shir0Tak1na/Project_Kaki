# Project Kaki：Phase 3 实施记录（Base 自定义视图）

> 目标：把地图数据与笔记**双向**连起来 —— 地图上的东西能在 Base 里被列出、筛选、点击跳转；
> 笔记只要写了坐标，就能出现在地图上。
>
> 本阶段**不把几何写进 `.base`**（`.base` 是 YAML），几何仍然只有一份：`.map.md` 里的 fenced JSON。

Phase 3 的 Base 视图和缩略图已完成主要实现；当前后续开发进入 Phase 4，先从 SVG 导出开始。

## 关键决定

### 1. `.base` 只放"指向"，不放几何

`.base` 是 YAML，而地图的几何（地形、路径、区域、顶点）体量大且需要原子写与撤销栈。
把它们塞进 YAML 会立刻产生三个问题：两份真相、无法撤销、Git diff 爆炸。
因此 `.base` 里只有视图选项 `mapFile: "Maps/World.map.md"`，几何仍然只有一份。

### 2. 数据准备全是纯函数，视图只管取数与画 DOM

`noteCoordinates.ts` / `mapRows.ts` 不 import obsidian。收益很直接：

- 坐标解析、两个来源的合并、排序稳定性、统计口径都能在 Node 里测（15 个测试）；
- 视图类的代码量被压到"取 config → 取 data → 渲染"这三件事。

### 3. Bases 的 `Value` 用**鸭子类型**取用，不用 `instanceof`

技术方案 §11 把"`Value` → 数字/字符串怎么取"列为未确认项。这里的选择是：
不 import `ListValue`/`NumberValue` 去做 `instanceof`，而是看它**有没有 `length()` 与 `get(i)`**
（列表）或 `toString()`（标量）。

理由不只是"少依赖"：`registerBasesView` 在旧版本上不存在，若代码里 import 了 `ListValue`，
在那些版本上该名字是 `undefined`，`x instanceof undefined` 会**直接抛 TypeError** ——
那会让"版本门禁 + 优雅降级"变成空话。鸭子类型没有这个问题，而且真实数据里的
`ListValue` / `NumberValue` / `StringValue` 都满足它。

### 4. 坐标写错要说出来，不能静默忽略

`coordinates: 东边那座城` 这种写法如果被静默忽略，用户看到的现象是"我的标记不见了"，
而他不会怀疑是拼写问题。因此 `NoteMapProps.invalid` 会把它标出来，
视图在表格下方列出这些笔记的路径。

### 5. 无坐标的条目要保留、排序时排最后

没有坐标的笔记仍然是有价值的行（"这个地点还没定位置"比"它不存在"更真实），
因此它们入表、坐标列显示 `—`；排序时**排在最后**而不是被当成 `0` 混在中间。

### 6. 选项缺失时仍然可用

- 没配 `mapFile`：如果库里只有一张地图，自动用它；否则只显示笔记侧的数据 +
  一行"怎么配"的提示。
- 配了但文件不存在：显示"找不到地图文档：路径"（红字），而不是留白。
- 完全不配任何选项：坐标属性有默认值（`note.coordinates` 等），开箱可用。

### 7. ⚠️ 自己在实现里踩的坑：忘了触发地图文档的加载

第一版 `onDataUpdated()` 只调用了 `render()`，从没调用 `loadMapDocument()` ——
表现是"表格里只有笔记，地图条目永远是 0"，而界面上**没有任何报错**。
是冒烟测试里那条"摘要显示地图路径与计数"把它抓出来的（当时显示"（未选择地图文档）"）。

教训与 §37/§4 一脉相承：**异步加载必须显式发起并有明确的可观测结果**
（这里是摘要里的地图路径与"地图条目 N"），否则缺失会伪装成"数据本来就少"。

### 8. 生成起始 `.base` 用真实 YAML 解析器验证

起始文件是"手写 YAML 容易错"的典型场景，因此：

- 生成逻辑是纯函数，**不猜语法**；
- 测试用 `yaml` 包真的解析一遍，并断言视图条目里的键值与代码里读的一致；
- 还测了"路径里带空格、引号、# 号"的往返，以及"不能出现制表符"。
- 过滤条件刻意**以注释形式**给出而不是写进文件：Base 过滤表达式写错会让整个文件打不开，
  而"少做一步"只是让用户多点一次。

（`yaml` 只作为 devDependency，不进插件产物。）

### 9. 缩略图是 SVG，不复制地图数据

Base 视图加载地图文档后，由 `mapPreview.ts` 直接生成一段 SVG：

- 地形按六边形格的真实世界顶点绘制；
- 路径、区域、标记和文字标注使用地图文档的世界坐标；
- 带坐标的笔记使用同一张行模型，因此不会出现“表格有、缩略图没有”的第二份筛选逻辑；
- 地图元素通过 `data-row-id` 对应到统一行模型，点击时由预览容器做事件代理并打开对应文件。
- 地图标记、文字、区域和路径都优先使用自身的 `link` 字段；没有链接时才回退到地图文档。

缩放时 X/Y 使用同一个 `scale = min(innerWidth / spanX, innerHeight / spanY)`，剩余空间作为居中留白。
这样预览框可以是任意长宽比，但地图本身不会被拉伸。

预览容器由 `ResizeObserver` 监听尺寸变化；重绘只替换 SVG 内容，不重建下面的表格。没有
`ResizeObserver` 的测试桩或旧环境使用稳定的回退尺寸，不影响 Base 表格工作。

- **视图选项在 `.base` 里的键名**：生成的文件写了 `mapFile:` 等键，但这依赖于
  "自定义选项就是视图条目的额外键"这一约定。若实际不生效，用户仍可在视图选项面板里重新选一次
  （这是刻意的设计：不配也能用）。请把实际现象告诉我；
- Base 的 `data` 是否在 `onDataUpdated` 前就绪（桩按真实契约模拟，但真实时序未验证）；
- 笔记属性被改后视图是否自动刷新（依赖 Bases 的 `onDataUpdated` 调用时机）；
- 大量条目（几百行）时的渲染性能（当前是一次性建表，未做虚拟滚动）。
- 缩略图中路径、区域、文字标注、地图标记和笔记点的真实点击跳转目标；测试桩已覆盖容器创建，真实库仍需逐项点击确认。
- 路径绘制或重命名后会弹出可选的“关联路径笔记”输入框；链接设置是独立的可撤销历史操作。
- 仍可直接在 `.map.md` 的路径对象中填写可选 `link` 字段，适合批量编辑或修复旧地图。
- 极端长宽比的 Base 容器中是否符合视觉预期（实现使用统一比例并留白，需真实库复核）。

## 当前能力边界

### 已实现的 Base 导航

- Base 表格同时列出地图条目与带坐标的笔记；
- 表格中的名称可以打开对应地图文档或笔记；
- 缩略图中的地图标记、路径、区域、文字标注和笔记坐标点使用统一行模型做点击跳转；
- 地形六边形目前只是视觉图层，没有单独文件，因此不能作为独立导航目标。

### 尚未实现的自定义地形图标

目前地形类型和视觉样式由代码内置，用户可以选择内置地形，但还不能在设置或地图文件中注册自己的地形图标、图块或纹理。
这项能力进入后续规划，预计包括：

1. 自定义地形类型名称、颜色和图标资源；
2. 自定义图块的缩放、旋转和变体；
3. 地形工具条动态读取用户地形库；
4. 地图文件保存自定义地形的稳定 ID，避免换图标后破坏已有地图。
