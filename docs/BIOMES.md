## 2. 不属于生物群系（**不要**加进目录）

设定明确：**地物不是生物群系** —— 例如「失乐园」「砂时间」「微光海」一类另有条目
（`地理概述.md` 末段原文即如此界定）。

实现上的含义：目录里**只放** §1 的分类；地物将来若要做，应该走**另一类对象**（例如新的选中种类），
不要塞进 `biome`。

## 3. 配色分组（给"分类配色表"用）

§D 要求把"渐变色带"扩展成**分类配色表**。建议按**气候带/层位**分组给色（同组色相相邻、跨组明显区分），
这样地图上一眼能看出"这是寒带还是热带"：

| 组 | 成员 | 色相建议 |
|---|---|---|
| 极地 / 寒带 | `ice-cap` `tundra` `conifer` | 冷白 → 蓝灰 → 深青 |
| 温带 | `temperate-broadleaf` `temperate-grassland` `mediterranean-sclerophyll` `montane-forest` | 中绿 → 黄绿 → 橄榄 → 深绿 |
| 高山 | `alpine-tundra` | 灰紫（与寒带区分） |
| 亚热带 / 季风 | `subtropical-rainforest` `subtropical-dry-forest` `monsoon-forest` | 青绿 → 黄褐 → 深青绿 |
| 热带 | `tropical-rainforest` `savanna` `tree-savanna` | 浓绿 → 金黄 → 橙绿 |
| 干旱 | `desert` `near-desert` `semi-arid-desert` `arid-grassland` | 沙黄 → 浅沙 → 土黄 → 暗金 |
| 地下 | 12 条 | 暗冷色系，**按 ID 顺序逐渐加深**（洞穴→湖→地狱） |
| 高空 | 4 条 | 亮浅色系（天蓝 → 云白 → 铅灰 → 亮青） |

具体色值由实现决定（建议放在**可整表替换**的配置里，与 §D 的目录工厂一致）。

## 4. 实现要点（与本仓库既有纪律对齐）

1. **数据**：`TerrainCell.biome?: string`；必须同时进
   `KNOWN_CELL_KEYS`（`src/data/mapDocument.ts:402`）与 `cellToJson` 的**固定顺序**，
   否则它会被当成"未知格字段"原样保留却**不参与渲染与统计**。
2. **未知 ID 一律保留**（§5.11）：别的库/别的版本写下的 biome ID 不许改写，渲染走回退。
3. **稳定 ID 不可改**：以上 ID 一旦发出去就写进用户的 `.map.md`；要改名只能"加新 ID + 迁移"
   （迁移机制已存在：见「改 ID 并迁移引用」）。
4. **目录工厂**：与自定义地形/标记同一套工厂；**内置集 = §1 的 34 条**（18+12+4），
   设置页注明"**分类表可整表替换**"。
5. **加一条分类 = 加一行**（与"加一个数据层字段 = 加两行"同一纪律）。
6. **不做**：不定义气候模型、不按纬度自动分配 biome（那是玩法，不是列表）；本轮只提供分类与配色。

## 5. 与本插件其它部分的关系

- **温度 / 深度**：设定给了行星参数（6 S⊕、自转 24 h、公转 540 天、轴倾角约 23.5°、3 颗卫星
  潮汐 9/15/40 天、恒星「元」F8V）。这些是将来"按纬度带推温度"的素材，**本轮不用**——
  温度仍由用户在格上手填或用笔刷加减。
- **图例**：用现有的"按类型计数"条目（`kind: 'types'`）即可。
- **笔刷**：枚举型 → 只有「设为某个 ID」。
